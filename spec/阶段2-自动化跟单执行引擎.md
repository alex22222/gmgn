## 1. 架构总览

阶段 2 自动化跟单执行引擎承接阶段 1 的聪明钱包池，实现**信号监听 → 智能决策 → 自动执行 → 闭环反馈**的完整链路。核心设计原则：

- **安全第一**：资金安全优先于收益，多层风控兜底
- **延迟容忍**：链上交易天然存在延迟，通过信号预处理降低影响
- **可观测性**：全链路日志、指标、告警，支撑 Loop Engineering 自我修正
- **模块化**：信号接收、决策引擎、执行器、风控、反馈循环解耦

## 2. 具体子目标（SMART 原则）

### 子目标 2.1：GMGN 信号接入层（Signal Ingestion Layer）

| SMART 维度 | 定义 |
|-----------|------|
| **S**pecific | 实现 GMGN 多源信号接入，支持 WebSocket 实时流、REST 轮询、gmgn-cli 事件三种信号源，覆盖目标聪明钱包的 Buy/Sell/Swap 事件。 |
| **M**easurable | 信号延迟 P95 < 3 秒（WebSocket）、信号丢失率 < 0.1%、目标钱包覆盖率 100%（无遗漏监控）。 |
| **A**chievable | 基于 gmgnapi（pip）和 gmgn-cli（npm）社区封装，已验证可获取数据。限速 2 次/秒可通过队列和批量请求管理。 |
| **R**elevant | 信号层是跟单执行的基础，信号延迟/丢失直接影响收益，必须优先实现。 |
| **T**ime-bound | 2 周内完成开发 + 1 周压力测试。 |

**验收标准：**
- [ ] 同时监听 ≥20 个聪明钱包地址，持续 7 天无丢包
- [ ] WebSocket 连接自动重连（指数退避，最大间隔 60 秒）
- [ ] 信号延迟中位数 < 1.5 秒，P95 < 3 秒
- [ ] 单元测试覆盖率 ≥80%
- [ ] 信号去重：同一笔交易 ID 不重复触发跟单决策

**失败回退：**
- 若 WebSocket 不稳定 → 降级为 REST 轮询（5 秒间隔）+ gmgn-cli 事件监听
- 若两者均失败 → 手动批量查询模式（10 分钟间隔），记录告警日志

### 子目标 2.2：信号预处理与过滤引擎（Signal Preprocessor）

| SMART 维度 | 定义 |
|-----------|------|
| **S**pecific | 对接收到的原始信号进行标准化、去重、过滤、增强，输出结构化交易信号。 |
| **M**easurable | 过滤准确率 > 95%（不误杀真实信号）、预处理吞吐量 > 100 信号/秒、端到端延迟 < 500ms。 |
| **A**chievable | 基于规则 + 启发式过滤，无复杂 ML 依赖。 |
| **R**elevant | 98.6% 的 Pump.fun 代币归零，前 100 名获利 300% 后续亏损 82%，必须严格过滤劣质信号。 |
| **T**ime-bound | 1 周内完成。 |

**核心过滤规则：**

| 规则编号 | 规则名称 | 条件 | 动作 | 备注 |
|---------|---------|------|------|------|
| F-01 | 机器人排除 | 7 天交易数 > 500 笔 | 丢弃信号 | 已知机器人特征 |
| F-02 | 小额过滤 | 单笔金额 < 50 USD | 丢弃信号 | 降低 Gas 浪费 |
| F-03 | 黑名单过滤 | 代币地址在黑名单 | 丢弃信号 | 已知跑路盘/貔貅盘 |
| F-04 | 重复买入冷却 | 同一钱包 1 小时内重复买入同一代币 | 丢弃信号 | 防止刷量干扰 |
| F-05 | 已毕业代币 | 代币已 Raydium 毕业 | 通过但标记 | 不同策略处理 |
| F-06 | 新币时间窗 | 代币创建 < 5 分钟 | 丢弃信号 | 避免早期陷阱 |
| F-07 | 流动性检查 | 池子流动性 < 2000 USD | 丢弃信号 | 防止滑点过大 |
| F-08 | 持有者检查 | 持有者 < 20 人 | 丢弃信号 | 早期风险 |

**验收标准：**
- [ ] 所有规则可配置（JSON/YAML），无需重启热加载
- [ ] 规则命中日志完整，支持审计追踪
- [ ] 过滤后信号保留率 15-30%（符合帕累托原则）
- [ ] 误过滤率（真实盈利信号被丢弃）< 5%

**失败回退：**
- 规则过于严格导致信号枯竭 → 逐步放宽阈值（如小额过滤从 50 USD 降至 20 USD）
- 误过滤率过高 → 启用影子模式（Shadow Mode）：过滤动作记录但不阻止信号，对比验证

### 子目标 2.3：跟单决策引擎（Copy-Trade Decision Engine）

| SMART 维度 | 定义 |
|-----------|------|
| **S**pecific | 基于预过滤信号，结合钱包评分、代币风险、市场环境、账户状态，输出是否跟单、跟单参数（金额、滑点、MEV 模式）。 |
| **M**easurable | 决策延迟 P95 < 200ms、每日跟单决策数 10-50 次、跟单胜率 > 50%（首月目标）。 |
| **A**chievable | 基于阶段 1 钱包评分 + 简单规则引擎，无需复杂模型。 |
| **R**elevant | 决策引擎是核心收益来源，直接决定跟单质量。 |
| **T**ime-bound | 2 周内完成。 |

**决策评分模型（Copy Signal Score, CSS）：**

```
CSS = w₁×WS + w₂×TR + w₃×MC + w₄×AC + w₅×TM

其中：
  WS  = Wallet Score（钱包评分，阶段 1 输出，0-100）
  TR  = Token Risk Score（代币风险评分，0-100，越高越安全）
  MC  = Market Condition Score（市场环境评分，0-100）
  AC  = Account Condition Score（账户状态评分，0-100）
  TM  = Time Momentum Score（时间动量评分，0-100）
  
  w₁=0.35, w₂=0.25, w₃=0.15, w₄=0.15, w₅=0.10（可配置）
  
决策阈值：
  CSS ≥ 70  → 高置信度，正常跟单
  50 ≤ CSS < 70 → 中等置信度，减半跟单
  CSS < 50  → 丢弃信号
```

**各子评分详细定义：**

**Token Risk Score (TR):**
```
TR = 基础分 100 - 风险扣分

风险扣分项：
  - 创建时间 < 1 小时: -30
  - 无流动性锁定: -20
  - 合约未开源: -15
  - 开发者有黑名单历史: -25
  - 同名/相似名诈骗: -20
  - 持仓集中度 Top 5 > 50%: -10
  - 税费 > 5%: -10
  - 最大单笔交易限制: -5
```

**Market Condition Score (MC):**
```
MC = 基础分 100 - 环境扣分

环境扣分项：
  - SOL 主网拥堵指数 > 80%: -20
  - 平均 Gas 费 > 0.05 SOL: -15
  - 链上 Swap 失败率 > 10%: -20
  - 过去 1 小时被夹（三明治攻击）> 3 次: -25
```

**Account Condition Score (AC):**
```
AC = 基础分 100 - 账户扣分

账户扣分项：
  - 当日已实现亏损 > 10% 本金: -30
  - 当日未实现亏损 > 20% 本金: -20
  - 连续 3 笔亏损: -15
  - 剩余 SOL < 0.5（无法支付 Gas）: -50（强制停止）
  - 当日已跟单次数 > 20: -10
```

**Time Momentum Score (TM):**
```
TM = 基于信号时效性的评分

  - 信号产生后 < 10 秒: 100
  - 10-30 秒: 80
  - 30-60 秒: 60
  - 60-120 秒: 40
  - > 120 秒: 20（通常不跟单，除非其他分极高）
```

**买入模式决策：**

| 模式 | 触发条件 | 计算方式 | 适用场景 |
|------|---------|---------|---------|
| Max Buy | 钱包 CSS > 85，且 TR > 80 | 使用预设最大单笔金额（如 2 SOL） | 高置信度信号，追求高回报 |
| Fixed Buy | 默认模式 | 固定金额（0.5-1 SOL/笔） | 常规跟单，风险控制 |
| Fixed Ratio | 跟单金额 = 目标钱包买入金额 × 比例（如 10%） | 比例可配置 | 大金额信号跟随 |

**验收标准：**
- [ ] CSS 计算延迟 P95 < 200ms
- [ ] 决策日志完整（输入信号、各子评分、最终 CSS、决策结果）
- [ ] 所有权重和阈值可配置，支持 A/B 测试
- [ ] 支持模拟模式（Paper Trading）：执行完整决策流程但不发真实交易

**失败回退：**
- 决策引擎 bug 导致误跟单 → 紧急模式：仅允许白名单钱包信号通过，其余全部丢弃
- 评分模型失效 → 回退至简单规则：仅跟单 Top 5 钱包，固定金额，标准止盈止损

### 子目标 2.4：交易执行器（Trade Executor）

| SMART 维度 | 定义 |
|-----------|------|
| **S**pecific | 实现 GMGN 交易下单执行，支持市价、限价、止盈止损、追踪止盈、追踪止损 5 种订单类型，集成 MEV 防护和滑点管理。 |
| **M**easurable | 下单成功率 > 95%、从决策到下单延迟 P95 < 5 秒、交易回执确认率 > 98%。 |
| **A**chievable | 基于 gmgn-cli 和社区 gmgnapi，已封装交易接口。 |
| **R**elevant | 执行器是资金操作入口，必须可靠、安全、可观测。 |
| **T**ime-bound | 2 周内完成。 |

**订单类型矩阵：**

| 订单类型 | GMGN 支持 | 使用场景 | 实现方式 |
|---------|----------|---------|---------|
| 市价单 | ✅ | 快速跟单（默认） | gmgn-cli buy 命令 |
| 限价单 | ✅ | 希望更优价格 | gmgn-cli buy --limit-price |
| 止盈止损 | ✅ | 自动风控 | gmgn-cli cooking 命令 |
| 追踪止盈 | ✅ | 趋势行情最大化收益 | gmgn-cli sell --trailing-stop |
| 追踪止损 | ✅ | 保护利润 | gmgn-cli sell --trailing-stop |
| 批量订单 | ✅ | 多钱包管理 | gmgn-cli 批量模式 |

**标准止盈止损策略（Cooking 模式）：**

```yaml
cooking_strategy:
  name: "标准分批止盈"
  description: "+100% 卖 50%，+300% 卖剩余 50%，-65% 止损全卖"
  
  entry:
    order_type: market
    slippage_mode: auto          # Auto / Turbo / Anti-MEV
    mev_protection: reduced      # Off / Reduced / Secure
    priority_fee_sol: 0.02       # 标准 0.01-0.03，竞争激烈时 0.05-0.1
    
  exit:
    take_profit_levels:
      - level: 1                 # 第一止盈位
        trigger: "+100%"         # 成本价翻倍
        sell_ratio: 0.50         # 卖出 50% 持仓
        order_type: limit        # 限价单，确保价格
      - level: 2
        trigger: "+300%"
        sell_ratio: 0.50         # 卖出剩余 50%（即总持仓的 25%）
        order_type: limit
    
    stop_loss:
      trigger: "-65%"
      sell_ratio: 1.00           # 全仓止损
      order_type: market         # 市价快速出逃
      
    # 可选：追加追踪止损（保护利润）
    trailing_stop:
      activate_at: "+200%"       # 盈利 200% 后激活
      callback_rate: 0.15        # 回撤 15% 触发
```

**保守策略（可选配置）：**

```yaml
conservative_strategy:
  take_profit_levels:
    - trigger: "+100%"    # 2X
      sell_ratio: 0.50
    - trigger: "+400%"    # 5X
      sell_ratio: 0.30
    - trigger: "+900%"    # 10X，ride
      sell_ratio: 0.20
  stop_loss:
    trigger: "-30%"         # 更严格止损
    sell_ratio: 1.00
```

**激进策略（可选配置）：**

```yaml
aggressive_strategy:
  stop_loss:
    trigger: "-40%"         # 更宽松止损，允许更大波动
  trailing_stop:
    activate_at: "+150%"
    callback_rate: 0.20
```

**滑点与 MEV 配置：**

| 场景 | 滑点模式 | MEV 防护 | 优先费 (SOL) | 说明 |
|------|---------|---------|------------|------|
| 日常交易 | Auto | Reduced | 0.01-0.03 | 默认配置 |
| 热门新币 | Turbo | Secure | 0.05-0.1 | 高竞争，快速成交 |
| 大额交易 | Anti-MEV | Secure | 0.05 | 防三明治攻击 |
| 紧急止损 | Turbo | Reduced | 0.1 | 快速出逃，优先成交 |

**执行流程：**

```
1. 接收决策引擎指令（代币、金额、策略、滑点模式）
2. 构建交易参数（检查余额、计算最小单位、设置滑点）
3. 调用 gmgn-cli 下单（或 gmgnapi Python 接口）
4. 等待交易回执（轮询或 WebSocket 监听）
5. 回执确认后，自动附加止盈止损条件单（cooking 模式）
6. 记录交易日志（tx_hash、gas_fee、实际滑点、确认时间）
7. 更新持仓状态
```

**私钥安全：**
- 私钥存储：`~/.config/gmgn/.env`，文件权限 `600`
- 环境变量读取，不硬编码
- 内存中短期持有，交易完成后立即清除
- 支持硬件钱包（后续扩展）

**验收标准：**
- [ ] 市价单成功率 > 95%（排除网络/链上问题）
- [ ] 从决策到链上确认延迟 P95 < 10 秒（在 Gas 费正常时）
- [ ] cooking 模式自动附加止盈止损条件单成功率 100%
- [ ] 交易失败自动重试（最多 3 次，每次退避 5 秒）
- [ ] 所有交易可审计（tx_hash、输入参数、实际结果、错误日志）
- [ ] 模拟交易模式完整（不消耗真实资金，记录预期结果）

**失败回退：**
- gmgn-cli 调用失败 → 重试 3 次 → 降级至 gmgnapi Python 接口 → 手动交易提醒
- 交易失败（如余额不足、滑点超限）→ 记录错误 → 跳过该信号 → 通知管理员
- 私钥读取失败 → 立即暂停所有交易 → 告警 → 等待人工修复

### 子目标 2.5：实时风控与熔断系统（Risk Control & Circuit Breaker）

| SMART 维度 | 定义 |
|-----------|------|
| **S**pecific | 实现多层实时风控：单笔风控、日累计风控、账户级风控、市场级熔断，防止大额亏损和系统性风险。 |
| **M**easurable | 风控触发延迟 < 100ms、单日最大亏损限制在 10% 本金以内、风控触发后 10 秒内停止所有新订单。 |
| **A**chievable | 基于规则引擎，实时计算账户状态，无外部依赖。 |
| **R**elevant | 98.6% 代币归零，必须严格风控保护本金。 |
| **T**ime-bound | 1.5 周完成。 |

**风控层级：**

```
Layer 1: 交易前风控（Pre-Trade）
  ├─ 余额检查：SOL 余额 > 0.5（Gas 预留）
  ├─ 单笔上限：单笔交易 ≤ 账户总价值的 5%（可配置）
  ├─ 同币上限：同一代币累计持仓 ≤ 账户总价值的 10%
  ├─ 日交易上限：每日跟单次数 ≤ 20 次
  ├─ 黑名单检查：代币地址不在黑名单
  └─ 冷却期：同一代币卖出后 1 小时内禁止再次买入

Layer 2: 交易中风控（In-Trade）
  ├─ 滑点监控：实际滑点 > 预设 1.5 倍 → 告警
  ├─ Gas 监控：Gas 费 > 0.1 SOL → 暂停（极端拥堵）
  ├─ 超时监控：交易提交后 60 秒未确认 → 标记为待处理，人工介入
  └─ 重复交易：同一 tx_hash 不重复执行

Layer 3: 交易后风控（Post-Trade）
  ├─ 日亏损熔断：当日已实现亏损 ≥ 10% → 暂停当日交易
  ├─ 连续亏损熔断：连续 5 笔亏损 → 暂停 2 小时
  ├─ 未实现亏损监控：未实现亏损 ≥ 20% → 告警，建议手动检查
  └─ 异常检测：单笔亏损 > 50% → 立即告警，调查原因

Layer 4: 市场级熔断（Market-Wide）
  ├─ 链上拥堵熔断：网络失败率 > 15% → 暂停 30 分钟
  ├─ 大范围跑路检测：过去 1 小时 ≥ 3 个持仓代币归零 → 紧急清仓
  └─ 重大事件熔断：手动触发，暂停所有交易（如协议漏洞、监管消息）
```

**熔断恢复机制：**

| 熔断类型 | 自动恢复 | 恢复条件 | 人工介入 |
|---------|---------|---------|---------|
| 日亏损熔断 | ❌ | 次日 00:00 UTC | 可选择提前恢复（需确认） |
| 连续亏损熔断 | ✅ | 暂停 2 小时后自动恢复 | 可手动延长 |
| Gas 拥堵熔断 | ✅ | 网络失败率 < 5% 持续 5 分钟 | 可手动恢复 |
| 大范围跑路 | ❌ | 需人工确认 | 必须人工检查每个持仓 |

**验收标准：**
- [ ] 所有风控规则可配置，支持热加载
- [ ] 风控触发后 10 秒内停止所有新订单（软停止，已有订单继续执行）
- [ ] 风控触发日志完整，包含触发原因、当前状态、建议动作
- [ ] 日亏损熔断测试：模拟 10% 亏损，确认交易停止
- [ ] 连续亏损熔断测试：模拟 5 笔连续亏损，确认 2 小时暂停
- [ ] 紧急清仓命令：一键市价卖出所有持仓（用于极端情况）

**失败回退：**

```python
    current_price_usd: Decimal     # 当前价格（USD）
    current_value_usd: Decimal     # 当前价值

@dataclass

    exit_tx_hash: str
    exit_time: datetime
    exit_price_usd: Decimal
    exit_amount_token: Decimal
    exit_amount_sol: Decimal

    pnl_ratio: Decimal
```

**盈亏计算逻辑：**

```python
# 已实现盈亏 = 所有卖出记录盈亏之和
realized_pnl = sum(r.pnl_usd for r in exit_records)

# 未实现盈亏 = 当前持仓价值 - 当前持仓成本
# 当前持仓成本 = 总买入成本 - 已卖出部分成本（按 FIFO）
current_cost_basis = total_entry_cost - sum(r.cost_basis_allocated for r in exit_records)
unrealized_pnl = current_value_usd - current_cost_basis

# 总盈亏 = 已实现 + 未实现
total_pnl = realized_pnl + unrealized_pnl
```

**实时更新机制：**

```
1. 事件驱动：交易成功后立即更新持仓
2. 定时轮询：每 30 秒查询一次所有持仓的当前价格
3. 价格源优先级：
   - 优先：GMGN 实时价格
   - 次选：Jupiter API
   - 备选：Raydium 池子直接计算
```

**验收标准：**
- [ ] 持仓数据与链上实际持有完全一致（可验证）
- [ ] 盈亏计算与手动核对误差 < 0.1%
- [ ] 支持持仓历史查询（任意时间点的持仓快照）
- [ ] 支持导出 CSV/JSON（税务/审计用途）
- [ ] 提供 REST API 查询持仓状态

**失败回退：**
- 价格源全部失效 → 使用最后已知价格，标记为 stale，暂停基于价格的决策
- 持仓数据不一致 → 触发全量重新扫描（从链上拉取所有 token 账户）

#### Loop 1：健康检查循环（Health Check Loop）

```yaml
触发: 每 5 分钟
```


#### Loop 3：策略自动修复循环（Strategy Auto-Repair Loop）

```yaml
触发: 每日 00:00 UTC
输入: 过去 24 小时交易数据

分析指标:
  - 整体胜率
  - 平均盈亏比
  - 策略 A vs 策略 B 的对比

  - 止损位命中率
```

#### Loop 4：风控参数调整循环（Risk Parameter Tuning Loop）


#### 4.2.1 信号去重算法

```python
def deduplicate_signal(signal: TradeSignal) -> bool:
    """
    返回 True 表示是新信号，False 表示重复
    """
    # 方法 1: 基于 tx_hash 精确去重（30 分钟窗口）
    if db.exists_signal_with_tx_hash(signal.tx_hash, window_minutes=30):
        return False
    
    # 方法 2: 基于钱包+代币+方向+金额模糊去重（5 分钟窗口）
    fuzzy_key = f"{signal.source_wallet}:{signal.token_address}:{signal.direction}:{round(signal.amount_sol, 2)}"
    if redis.exists(fuzzy_key, ttl_seconds=300):
        return False
    
    # 记录指纹
    redis.set(fuzzy_key, signal.signal_id, ttl_seconds=300)
    return True
```

#### 4.2.2 过滤引擎

```python
class SignalFilterEngine:
    def __init__(self, config: FilterConfig):
        self.rules = [
            RobotFilterRule(),          # F-01
            MinAmountFilterRule(),      # F-02
            BlacklistFilterRule(),      # F-03
            CooldownFilterRule(),       # F-04
            GraduatedFilterRule(),      # F-05
            NewTokenFilterRule(),       # F-06
            LiquidityFilterRule(),      # F-07
            HolderFilterRule(),         # F-08
        ]
    
    def filter(self, signal: TradeSignal) -> FilterResult:
        results = []
        for rule in self.rules:
            result = rule.evaluate(signal)
            results.append(result)
            if result.action == FilterAction.DROP:
                return FilterResult(
                    passed=False,
                    rule_hits=[r for r in results if r.action == FilterAction.DROP],
                    passed_rules=[r for r in results if r.action == FilterAction.PASS]
                )
        
        return FilterResult(
            passed=True,
            rule_hits=[],
            passed_rules=results
        )
```

```python
    # 1. Wallet Score (WS) - 直接使用阶段 1 输出
    wallet = db.get_wallet(signal.source_wallet)
    ws = wallet.wallet_score
    
    # 2. Token Risk Score (TR)
    tr = calculate_token_risk(signal.token_address)
    
    # 3. Market Condition Score (MC)
    mc = calculate_market_condition()
    
    # 4. Account Condition Score (AC)
    ac = calculate_account_condition(portfolio)
    
    # 5. Time Momentum Score (TM)
    tm = calculate_time_momentum(signal.received_at)
    
    # 加权求和
    weights = config.scoring.weights
    css = (
        weights["wallet_score"] * ws +
        weights["token_risk"] * tr +
        weights["market_condition"] * mc +
        weights["account_condition"] * ac +
        weights["time_momentum"] * tm
    )
    
    return DecisionScore(
        wallet_score=ws,
        token_risk_score=tr,
        market_condition_score=mc,
        account_condition_score=ac,
        time_momentum_score=tm,
        final_css=css,
        weights=weights
    )

def calculate_token_risk(token_address: str) -> Decimal:
    """代币风险评分：100 - 风险扣分"""
    score = Decimal("100")
    token_info = gmgn.get_token_info(token_address)
    
    if token_info.age_minutes < 60:
        score -= 30
    if not token_info.liquidity_locked:
        score -= 20
    if not token_info.contract_open_source:
        score -= 15
    if token_info.dev_blacklist_history:
        score -= 25
    if token_info.is_honeypot:
        score -= 50  # 直接标记为高风险
    if token_info.top5_holder_pct > 50:
        score -= 10
    if token_info.tax_pct > 5:
        score -= 10
    
    return max(score, Decimal("0"))

def calculate_market_condition() -> Decimal:
    """市场环境评分"""
    score = Decimal("100")
    
    # 链上拥堵
    congestion = get_network_congestion()
    if congestion > 0.8:
        score -= 20
    elif congestion > 0.6:
        score -= 10
    
    # Gas 费
    avg_gas = get_avg_gas_fee()
    if avg_gas > Decimal("0.05"):
        score -= 15
    elif avg_gas > Decimal("0.03"):
        score -= 5
    
    # Swap 失败率
    failure_rate = get_swap_failure_rate(minutes=60)
    if failure_rate > 0.1:
        score -= 20
    elif failure_rate > 0.05:
        score -= 10
    
    # 被夹检测
    sandwich_count = get_sandwich_attack_count(minutes=60)
    if sandwich_count > 3:
        score -= 25
    
    return max(score, Decimal("0"))

def calculate_account_condition(portfolio: PortfolioState) -> Decimal:
    """账户状态评分"""
    score = Decimal("100")
    
    # 当日已实现亏损
    daily_realized_pnl = portfolio.get_daily_realized_pnl()
    if daily_realized_pnl < -portfolio.total_value * Decimal("0.10"):
        score -= 30
    elif daily_realized_pnl < -portfolio.total_value * Decimal("0.05"):
        score -= 15
    
    # 未实现亏损
    unrealized_pnl = portfolio.get_total_unrealized_pnl()
    if unrealized_pnl < -portfolio.total_value * Decimal("0.20"):
        score -= 20
    
    # 连续亏损
    consecutive_losses = portfolio.get_consecutive_losses()
    if consecutive_losses >= 3:
        score -= 15
    
    # SOL 余额
    sol_balance = portfolio.get_sol_balance()
    if sol_balance < Decimal("0.5"):
        score -= 50  # 强制停止
    
    # 日交易次数
    daily_trades = portfolio.get_daily_trade_count()
    if daily_trades > 20:
        score -= 10
    
    return max(score, Decimal("0"))

def calculate_time_momentum(received_at: datetime) -> Decimal:
    """时间动量评分：信号越新越好"""
    elapsed_seconds = (datetime.utcnow() - received_at).total_seconds()
    
    if elapsed_seconds <= 10:
        return Decimal("100")
    elif elapsed_seconds <= 30:
        return Decimal("80")
    elif elapsed_seconds <= 60:
        return Decimal("60")
    elif elapsed_seconds <= 120:
        return Decimal("40")
    else:
        return Decimal("20")
```

```python
def calculate_buy_amount(decision: TradeDecision, portfolio: PortfolioState) -> Decimal:
    """根据买入模式计算实际买入金额"""
    
    if decision.buy_mode == BuyMode.MAX_BUY:
        # 使用预设最大单笔金额
        amount = config.account.max_single_trade_sol
    
    elif decision.buy_mode == BuyMode.FIXED_BUY:
        # 固定金额（默认 0.5-1 SOL）
        amount = Decimal("0.5")  # 可配置
    
    elif decision.buy_mode == BuyMode.FIXED_RATIO:
        # 按比例跟随源钱包
        source_signal = db.get_signal(decision.signal_id)
        ratio = Decimal("0.10")  # 10% 比例，可配置
        amount = source_signal.amount_sol * ratio
    
    # 检查是否超过账户上限
    max_by_pct = portfolio.total_value_sol * config.account.max_single_trade_pct
    amount = min(amount, max_by_pct)
    
    # 检查是否超过单笔上限
    amount = min(amount, config.account.max_single_trade_sol)
    
    # 检查 SOL 余额（预留 Gas）
    sol_balance = portfolio.get_sol_balance()
    max_spend = sol_balance - config.account.min_sol_balance
    amount = min(amount, max_spend)
    
    # 检查是否超过同币上限
    current_exposure = portfolio.get_token_exposure(decision.token_address)
    max_token_exposure = portfolio.total_value_sol * config.account.max_token_exposure_pct
    remaining = max_token_exposure - current_exposure
    amount = min(amount, remaining)
    
    # 如果金额过小，放弃交易
    if amount < Decimal("0.1"):
        raise InsufficientBalance("余额不足或超过暴露限制")
    
    return amount
```

```python
def calculate_tp_sl_orders(entry_price: Decimal, strategy: Strategy) -> List[TpSlOrder]:
    """基于买入价计算止盈止损条件单"""
    orders = []
    
    # 止盈单
    for level in strategy.take_profit_levels:
        trigger_price = entry_price * (1 + level.trigger_ratio)
        orders.append(TpSlOrder(
            order_type="TAKE_PROFIT",
            trigger_price_usd=trigger_price,
            sell_ratio=level.sell_ratio,
            status="PENDING"
        ))
    
    # 止损单
    sl_trigger = entry_price * (1 + strategy.stop_loss.trigger_ratio)
    orders.append(TpSlOrder(
        order_type="STOP_LOSS",
        trigger_price_usd=sl_trigger,
        sell_ratio=strategy.stop_loss.sell_ratio,
        status="PENDING"
    ))
    
    # 追踪止损（可选）
    if strategy.trailing_stop:
        orders.append(TpSlOrder(
            order_type="TRAILING_STOP",
            activate_price=entry_price * (1 + strategy.trailing_stop.activate_ratio),
            callback_rate=strategy.trailing_stop.callback_rate,
            status="PENDING"
        ))
    
    return orders
```

```python
def select_execution_mode(token: TokenInfo, market: MarketState, amount_sol: Decimal) -> ExecutionMode:
    """根据代币和市场状态选择最优执行模式"""
    
    # 默认
    slippage_mode = SlippageMode.AUTO
    mev_protection = MevProtection.REDUCED
    priority_fee = config.execution.default_priority_fee_sol
    
    # 高竞争场景判断
    is_hot = token.is_trending or token.buy_pressure > 0.7
    is_large = amount_sol > Decimal("1.0")
    is_high_risk = token.age_minutes < 30
    
    if is_hot and is_high_risk:
        # 热门新币：激进执行
        slippage_mode = SlippageMode.TURBO
        mev_protection = MevProtection.SECURE
        priority_fee = config.execution.turbo_priority_fee_sol
    
    elif is_large:
        # 大额交易：防 MEV
        slippage_mode = SlippageMode.ANTI_MEV
        mev_protection = MevProtection.SECURE
        priority_fee = config.execution.turbo_priority_fee_sol
    
    elif market.congestion > 0.8:
        # 网络拥堵：提高优先费
        priority_fee = config.execution.turbo_priority_fee_sol
    
    return ExecutionMode(
        slippage_mode=slippage_mode,
        mev_protection=mev_protection,
        priority_fee_sol=priority_fee
    )
```

```python
class BacktestEngine:
    """
    基于历史信号数据的回测引擎
    """
    
    def run(self, signals: List[TradeSignal], config: BacktestConfig) -> BacktestResult:
        portfolio = VirtualPortfolio(initial_sol=10.0)

            portfolio.update_position(execution)
            
            # 6. 检查止盈止损（基于历史价格数据）
            self.check_tp_sl(portfolio, signal.tx_time)
        
        return BacktestResult(
            total_trades=portfolio.total_trades,
            win_rate=portfolio.win_rate,
            total_pnl=portfolio.total_pnl,
            max_drawdown=portfolio.max_drawdown,
            sharpe_ratio=portfolio.sharpe_ratio,
```

## 7. 失败回退策略汇总

### 7.1 模块级回退

| 模块 | 故障场景 | 回退策略 | 恢复条件 |
|------|---------|---------|---------|
| 信号接入 | WebSocket 断开 | 降级为 REST 轮询 + CLI 事件 | WebSocket 重连成功并稳定 5 分钟 |
| 信号接入 | 全部信号源失败 | 手动批量查询模式（10 分钟间隔） | 任一信号源恢复 |
| 过滤引擎 | 规则过于严格 | 逐步放宽阈值，启用影子模式 | 信号保留率恢复到 15-30% |
| 决策引擎 | Bug 导致误跟单 | 白名单模式（仅 Top 5 钱包） | Bug 修复 + 测试通过 |
| 交易执行 | gmgn-cli 失败 | 重试 3 次 → gmgnapi → 手动提醒 | 交易成功或人工确认 |
| 交易执行 | 私钥读取失败 | 立即暂停所有交易 | 私钥文件修复 |
| 风控系统 | 自身故障 | 默认拒绝所有交易（安全模式） | 风控系统修复 |
| 持仓追踪 | 价格源全部失效 | 使用最后已知价格，标记 stale | 任一价格源恢复 |
| 持仓追踪 | 数据不一致 | 全量重新扫描链上账户 | 数据一致 |
| 反馈循环 | 自身故障 | 告警，不影响主交易流程 | 修复后重启 |
| 监控系统 | 告警通道故障 | 备用通道自动切换 | 主通道恢复 |

### 7.2 系统级回退

| 场景 | 回退策略 | 触发条件 |
|------|---------|---------|
| 紧急停止 | 一键停止所有新交易，保留已有持仓 | 用户手动触发 / P0 事件 |
| 紧急清仓 | 一键市价卖出所有持仓 | 用户确认 / 大范围跑路检测 |
| 模拟模式 | 所有交易走模拟，不发真实订单 | 参数回滚测试 / 新策略验证 |
| 保守模式 | 仅跟单 Top 5 钱包，固定金额，标准策略 | 连续亏损 5 笔 / 日亏损 5% |
| 单钱包模式 | 仅跟踪 1 个最可靠钱包 | 系统异常 / 测试环境 |

### 7.3 数据级回退

| 场景 | 回退策略 |
|------|---------|
| 参数调整失败 | 一键回滚到上一版本配置 |
| 数据库损坏 | 从最近一次备份恢复（建议每日备份） |
| 配置丢失 | 使用默认安全配置启动 |
| 交易记录丢失 | 从链上重新扫描重建 |
