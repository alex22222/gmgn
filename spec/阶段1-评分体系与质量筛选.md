# 阶段1：评分体系与质量筛选 — 详细实现规范

> 版本：v1.0  
> 对应系统：GMGN扫链聪明钱包发现+自动化跟单系统  
> 状态：设计阶段（未实现）  
> 上游依赖：现有 `gmgn_monitor` 监控框架（Phase 1 已完成）  
> 下游目标：阶段2 自动化跟单交易执行层

---

## 1. 项目定位与边界

### 1.1 当前系统状态
现有 `gmgn_monitor` 已完成 **Phase 1-5** 的监控层建设，具备：
- 候选代币的评分与决策（reject/watch/alert）
- 安全边界（无交易执行、无私钥操作）
- 可配置阈值与验证闭环
- 本地Dashboard与干跑Pipeline

### 1.2 阶段1新目标
在现有监控层之上，新增 **聪明钱包发现层（Smart Wallet Intelligence Layer）**，实现：
- 从链上数据/GMGN抓取高胜率钱包地址
- 建立多维度钱包评分体系（非代币评分）
- 对优质钱包进行模拟回测（Paper Trading）
- 输出可跟单钱包列表，为阶段2提供交易信号源

### 1.3 安全边界（与现有系统一致）
- ❌ 禁止任何私钥操作、签名、交易提交
- ❌ 禁止自动买入/卖出执行
- ❌ 禁止Telegram/飞书等外部网络发送（仅本地干跑文件）
- ✅ 允许只读数据抓取、评分计算、回测模拟、本地文件输出

### 2.2 子目标详细定义

#### SG-1：链上钱包数据抓取与清洗

**Specific（具体）**：构建多源钱包数据抓取管道，从GMGN WebSocket、公开API、链上RPC获取钱包列表及其交易历史，并进行数据清洗去重。

**Measurable（可衡量）**：
- 日抓取活跃钱包数 ≥ 5,000（活跃定义为7天内有交易）
- 清洗后有效钱包比例 ≥ 80%（去重、去空、格式校验通过）
- 每个钱包交易历史深度 ≥ 100笔（或全部历史）
- 数据完整性：必填字段缺失率 ≤ 2%

**Achievable（可达成）**：
- GMGN WebSocket限速2次/秒，可配合IP白名单提升
- 社区GmGnAPI（pip）提供Python封装
- gmgn-cli（npm）提供CLI抓取能力
- 多链支持：Solana（优先）、Base、BSC

**Relevant（相关性）**：上游数据质量直接决定下游评分与回测准确性。

**Time-bound（时限）**：第1-2周完成。

**验收标准**：
- [ ] 运行 `python3 -m gmgn_wallet.fetch --days 7 --output data/wallets_raw.jsonl` 输出≥5000条有效记录
- [ ] 运行 `python3 -m gmgn_wallet.validate --input data/wallets_raw.jsonl` 返回有效记录率≥80%
- [ ] 单元测试覆盖率≥80%，所有schema验证通过

---

#### SG-2：钱包交易历史解析与特征工程

**Specific（具体）**：将原始交易数据解析为结构化特征，包括盈亏计算、交易频率、持仓周期、代币偏好等。

**Measurable（可衡量）**：
- 100%已抓取钱包完成交易历史解析
- 特征维度≥20个（见第3章数据模型）
- 特征计算准确率：盈亏计算误差≤1%（以链上实际数据为准）
- 异常交易标记率≥95%（刷量、自转、合约交互等）

**Achievable（可达成）**：
- Solana有成熟的交易解析库（solana-py、anchorpy）
- DEX交易可通过日志事件解析（Swap、Transfer、Mint等）
- 盈亏计算基于买入/卖出事件配对（FIFO或加权平均）

**Relevant（相关性）**：特征是评分体系的核心输入。

**Time-bound（时限）**：第2-3周完成。

**验收标准**：
- [ ] 运行 `python3 -m gmgn_wallet.features --input data/wallets_raw.jsonl --output data/wallets_features.jsonl` 输出100%记录
- [ ] 随机抽样50个钱包，人工核对盈亏计算准确率≥99%
- [ ] 所有特征字段无NaN/Infinity异常值

---

#### SG-3：多维度评分体系构建

**Specific（具体）**：构建6维度钱包评分体系，总分0-100，输出分级（优质/关注/观察/淘汰）。

**Measurable（可衡量）**：
- 6个维度：盈利能力、风险控制、交易纪律、市场敏锐度、资金管理、稳定性
- 每个维度权重可配置（配置文件驱动）
- 优质钱包（≥80分）占比≤5%
- 淘汰钱包（≤30分）占比≥50%
- 评分与回测收益相关性Pearson r ≥ 0.6

**Achievable（可达成）**：
- 基于成熟量化投资框架（类似基金评级体系）
- 权重可通过配置文件动态调整，无需改代码
- 评分可复算（给定相同输入和配置，输出一致）

**Relevant（相关性）**：评分体系是跟单决策的核心依据。

**Time-bound（时限）**：第3-4周完成。

**验收标准**：
- [ ] 运行 `python3 -m gmgn_wallet.score --input data/wallets_features.jsonl --config config/scoring_weights.json --output data/wallets_scored.jsonl` 正常输出
- [ ] 评分分布呈正态或偏态，无异常聚集
- [ ] 优质钱包（≥80分）经人工抽检，准确率≥70%
- [ ] 单元测试覆盖所有维度计算

#### SG-4：质量筛选与过滤规则

**Specific（具体）**：建立10+条过滤规则，排除机器人、刷量钱包、MEV bot、冲盘钱包等噪声。

**Measurable（可衡量）**：
- 过滤规则≥10条，每条规则可独立开关
- 机器人识别率≥90%（以已知机器人地址为基准测试）
- 误杀率（优质钱包被过滤）≤15%
- 过滤后有效钱包数 ≤ 原始数量的30%

**Achievable（可达成）**：
- 基于交易频率、Gas模式、盈利分布、时间模式等特征识别
- 参考已知机器人地址黑名单（社区维护）
- 可调节阈值，避免过度过滤

**Relevant（相关性）**：过滤质量决定跟单信号的信噪比。

**Time-bound（时限）**：第3-4周完成。

**验收标准**：
- [ ] 运行 `python3 -m gmgn_wallet.filter --input data/wallets_scored.jsonl --config config/filter_rules.json --output data/wallets_filtered.jsonl` 正常输出
- [ ] 使用已知100个机器人地址测试，识别率≥90%
- [ ] 使用已知50个优质钱包测试，误杀率≤15%
- [ ] 过滤规则可配置，支持热重载（无需重启）

#### SG-5：模拟回测引擎

**Specific（具体）**：构建Paper Trading回测引擎，支持3种跟单模式（Max Buy、Fixed Buy、Fixed Ratio），输出回测收益、夏普比率、最大回撤。

**Measurable（可衡量）**：
- 支持3种买入模式：Max Buy、Fixed Buy（0.5-1 SOL/笔）、Fixed Ratio
- 支持标准止盈止损策略：+100%卖50%，+300%卖剩余50%，止损-65%全卖
- 回测周期≥30天，覆盖≥100个钱包的完整交易历史
- 输出指标：总收益率、年化收益率、夏普比率、最大回撤、胜率、盈亏比
- 回测结果可复现（给定相同输入和参数，输出一致）

**Achievable（可达成）**：
- 基于历史交易数据模拟跟单执行
- 考虑滑点（20-30%）、手续费（1%）、优先费（0.01-0.1 SOL）
- 支持滑点模式：Auto / Turbo / Anti-MEV

**Relevant（相关性）**：回测验证评分体系的有效性和跟单策略的可行性。

**Time-bound（时限）**：第4-5周完成。

**验收标准**：
- [ ] 运行 `python3 -m gmgn_wallet.backtest --input data/wallets_filtered.jsonl --strategy config/backtest_strategy.json --output data/backtest_results.jsonl` 正常输出
- [ ] 回测结果包含完整指标（收益、夏普、回撤、胜率、盈亏比）
- [ ] 回测结果可复现：同输入同参数连续运行3次，结果差异≤0.1%
- [ ] 回测日志包含每笔模拟交易的详细记录（时间、价格、数量、费用、滑点）

## 3. 输入/输出数据模型

### 3.1 钱包原始数据（WalletRawRecord）

```json
{
  "wallet_address": "7xKXtg2CW87d97TXJSDpbD5jBkheTqA83TZR6Y7Q5XqK",
  "chain": "solana",
  "first_seen_at": "2025-01-15T08:30:00Z",
  "last_active_at": "2025-07-03T12:00:00Z",
  "total_transactions": 342,
  "source": "gmgn_ws",
  "fetched_at": "2025-07-03T12:00:00Z",
  "raw_data_hash": "sha256:abc123..."
}
```

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `wallet_address` | string | 非空，链上合法地址格式 | 钱包地址 |
| `chain` | string | enum: solana, base, bsc | 所属链 |
| `first_seen_at` | string | ISO 8601 timestamp | 首次观察时间 |
| `last_active_at` | string | ISO 8601 timestamp | 最后活跃时间 |
| `total_transactions` | integer | ≥0 | 总交易笔数 |
| `source` | string | 非空 | 数据来源：gmgn_ws、rpc、api等 |
| `fetched_at` | string | ISO 8601 timestamp | 抓取时间 |
| `raw_data_hash` | string | 非空 | 原始数据SHA256哈希，用于去重 |

## 4. 算法/逻辑设计

### 4.1 评分体系核心算法

#### 4.1.1 总分计算公式

```
TotalScore = Σ(DimensionScore_i × Weight_i) × QualityMultiplier

其中：
- DimensionScore_i ∈ [0, 100]：第i个维度得分
- Weight_i ∈ [0, 1]：第i个维度权重，ΣWeight_i = 1.0
- QualityMultiplier ∈ [0, 1]：质量惩罚系数（根据风险标记调整）

QualityMultiplier计算：
  若任意 risk_flag = true: 乘以 0.5（严重惩罚）
  若 bot_pattern_score > 20: 乘以 0.7
  若 win_rate < 50%: 乘以 0.8
  否则: 1.0
```

#### 4.1.2 六维度评分算法

**维度1：盈利能力（Profitability）—— 权重25%**

```python
def score_profitability(features):
    # 基础分：综合多个盈利指标
    base = 0
    
    # 胜率（40%权重）
    win_rate = features.profit_metrics.win_rate_percent
    if win_rate >= 70: base += 40
    elif win_rate >= 60: base += 32
    elif win_rate >= 50: base += 20
    else: base += max(0, win_rate * 0.4)
    
    # 盈亏比（30%权重）
    pl_ratio = features.profit_metrics.profit_loss_ratio
    if pl_ratio >= 3.0: base += 30
    elif pl_ratio >= 2.0: base += 24
    elif pl_ratio >= 1.5: base += 18
    else: base += max(0, pl_ratio * 10)
    
    # 30天利润（30%权重）
    profit_30d = features.profit_metrics.profit_sol_30d
    avg_position = features.capital_metrics.avg_position_sol
    if avg_position > 0:
        roi_30d = profit_30d / (avg_position * features.frequency_metrics.trades_30d)
    else:
        roi_30d = 0
    
    if roi_30d >= 0.5: base += 30
    elif roi_30d >= 0.3: base += 24
    elif roi_30d >= 0.1: base += 18
    else: base += max(0, roi_30d * 60)
    
    return min(100, base)
```

### 4.4 机器人识别算法

```python
def detect_bot(features):
    """
    综合机器人识别，返回 bot_score [0, 100]
    分数越高，机器人概率越大
    """
    score = 0
    
    # 1. 交易频率异常（权重30%）
    trades_per_day = features.frequency_metrics.avg_daily_trades
    if trades_per_day > 100: score += 30
    elif trades_per_day > 50: score += 20
    elif trades_per_day > 30: score += 10
    
    # 2. 时间模式异常（权重25%）—— 交易时间分布是否均匀（机器人24小时均匀，人类有睡眠周期）
    time_uniformity = calculate_time_uniformity(features)  # 0-1
    if time_uniformity > 0.85: score += 25
    elif time_uniformity > 0.7: score += 15
    
    # 3. Gas模式异常（权重20%）—— 固定Gas偏好
    gas_variance = calculate_gas_variance(features)
    if gas_variance < 0.1: score += 20  # Gas几乎固定
    elif gas_variance < 0.2: score += 10
    
    # 4. 交互模式（权重15%）—— 是否只与合约交互，极少与普通地址交互
    contract_interaction_rate = features.behavioral_metrics.contract_interaction_rate
    if contract_interaction_rate > 0.95: score += 15
    elif contract_interaction_rate > 0.9: score += 10
    
    # 5. 盈利模式（权重10%）—— 是否总是微盈或微亏，无大波动
    pnl_std = features.profit_metrics.pnl_std
    avg_pnl = abs(features.profit_metrics.avg_profit_per_trade_sol)
    if avg_pnl > 0 and pnl_std / avg_pnl < 0.3: score += 10
    
    return min(100, score)
```

**阈值**：
- bot_score ≥ 60：高度怀疑机器人，硬过滤
- 40 ≤ bot_score < 60：可能半自动，软过滤-10分
- bot_score < 40：正常人类交易者

### 5.2 五个核心反馈循环

#### 循环1：数据质量反馈环（Data Quality Loop）

**目标**：确保上游数据质量，及时发现抓取异常。

**触发条件**：
- 每日运行后自动触发
- 数据完整性率<95%时立即触发
- 钱包地址重复率>10%时触发

**度量指标**：
- 数据完整性率 = 有效字段数 / 总字段数 ≥ 98%
- 地址重复率 = 重复地址数 / 总地址数 ≤ 5%
- 交易解析成功率 ≥ 99%
- 时间戳异常率 ≤ 1%

**自动修正**：
- 完整性率<95%：暂停评分，发出告警，检查数据源
- 重复率>10%：自动去重，记录去重日志
- 解析失败>1%：重试失败交易，记录错误日志

**参数调整**：
- 若某数据源持续失败>3天，降低该源权重或停用
- 配置文件：`config/data_sources.json`

#### 循环2：评分验证反馈环（Scoring Validation Loop）

**目标**：验证评分体系与真实收益的相关性。

**触发条件**：
- 每周日自动运行（积累7天数据）
- 评分与回测收益相关性 r<0.5时立即触发
- 优质钱包（≥80分）人工抽检准确率<70%时触发

**度量指标**：
- Pearson相关系数 r ≥ 0.6（评分 vs 回测收益）
- 人工标注准确率 ≥ 75%
- 优质钱包实际表现优于大盘的概率 ≥ 70%
- 淘汰钱包（≤30分）实际亏损率 ≥ 80%

**自动修正**：
- r<0.5：触发参数自动搜索（Grid Search）
- 人工准确率<70%：调整维度权重，增加人工标注样本
- 优质钱包表现差：检查该维度定义是否合理

**参数调整**：
- 维度权重微调范围：±5%
- 阈值调整范围：±10%
- 调整记录保存：`data/score_tuning_history.jsonl`
- A/B测试：新参数与旧参数并行运行1周，对比效果

#### 循环3：过滤规则反馈环（Filter Rule Loop）

**目标**：优化过滤规则，降低误杀率，提高机器人识别率。

**触发条件**：
- 每周运行后自动触发
- 误杀率>15%时触发
- 机器人识别率<85%时触发

**度量指标**：
- 误杀率 = 被过滤的优质钱包 / 总优质钱包 ≤ 15%
- 机器人识别率 = 正确识别的机器人 / 总机器人 ≥ 90%
- 过滤后有效钱包比例：原始数量的20-30%
- 过滤后优质钱包密度提升倍数 ≥ 3x

**自动修正**：
- 误杀率>15%：放宽相关阈值，增加白名单机制
- 识别率<85%：收紧机器人特征阈值，增加新特征
- 过滤后钱包过多（>40%）：收紧规则
- 过滤后钱包过少（<15%）：放宽规则

**参数调整**：
- 规则阈值：±20%
- 新增/删除规则：需人工审核
- 规则版本控制：`config/filter_rules.json` 纳入Git管理

#### 循环4：回测策略反馈环（Backtest Strategy Loop）

**目标**：优化跟单策略参数，提高回测收益和稳定性。

**触发条件**：
- 每月运行后自动触发
- 夏普比率<1.0时触发
- 最大回撤>50%时触发
- 胜率<55%时触发

**度量指标**：
- 夏普比率 ≥ 1.5（优质）/ ≥ 1.0（可接受）
- 最大回撤 ≤ 40%（保守）/ ≤ 50%（激进）
- 胜率 ≥ 60%
- 盈亏比 ≥ 2.0
- 年化收益 ≥ 300%（Meme币市场）

**自动修正**：
- 夏普<1.0：调整止盈止损比例，测试新策略
- 回撤>50%：收紧止损，增加仓位控制
- 胜率<55%：提高评分阈值，只跟更高分钱包

**参数调整**：
- 止盈步长：测试 [2X/3X/5X]、[2X/5X/10X]、[3X/5X/10X] 组合
- 止损比例：测试 -30%、-40%、-50%、-65%
- 仓位大小：测试 0.5/1.0/2.0 SOL
- 策略比较：保存最优策略配置到 `config/backtest_strategy.json`

#### 循环5：人工验证反馈环（Human Review Loop）

**目标**：人工审核关键决策，确保系统不偏离预期。

**触发条件**：
- 每周人工审核日（固定周日）
- 评分异常波动（标准差>2倍历史均值）时触发
- 新增优质钱包>20%时触发（可能市场异常）
- 系统连续3天无优质钱包产出时触发

**度量指标**：
- 人工审核覆盖率：每周至少50个钱包
- 人工与系统一致性：≥75%
- 人工发现系统误判率：≤10%
- 审核完成时间：≤2小时/周

**自动修正**：
- 一致性<75%：标记待调优维度，增加训练样本
- 误判率>10%：暂停自动调优，人工介入分析
- 市场异常：调整评分参数，降低阈值敏感度
- 无产出>3天：检查数据源和过滤规则，确认系统正常

**参数调整**：
- 人工审核结果直接写入：`data/human_review.jsonl`
- 审核结果自动参与下次参数调优
- 重大误判触发紧急审查：冻结自动调整，等待人工确认

## 7. 失败回退策略

### 7.1 子目标失败回退

#### SG-1 失败回退：数据抓取失败

**场景**：GMGN WebSocket连接失败、IP被封禁、数据格式变更

**回退层级**：
1. **L1 - 自动重试**：指数退避重试（1s, 2s, 4s, 8s, 16s），最多5次
2. **L2 - 切换数据源**：降级到备用数据源（DEX Screener API、链上RPC）
3. **L3 - 使用历史数据**：读取最近7天的本地缓存，继续运行（标记为stale）
4. **L4 - 人工介入**：暂停自动运行，发送告警（本地日志），等待人工修复

**恢复标准**：
- 连续成功抓取3天且无数据质量问题，恢复正常运行
- 人工确认数据源修复后，清除stale标记

#### SG-2 失败回退：特征计算失败

**场景**：交易解析错误、链上数据缺失、新类型交易未适配

**回退层级**：
1. **L1 - 跳过异常**：记录错误钱包地址，跳过该钱包，继续处理其他钱包
2. **L2 - 降级计算**：使用简化特征（仅基础统计，不计算复杂指标）
3. **L3 - 缓存复用**：读取上次计算的特征缓存（如果缓存时间<7天）
4. **L4 - 人工介入**：暂停评分，标记待处理钱包，等待人工分析

**恢复标准**：
- 错误率<5%：自动恢复，标记错误钱包为待处理
- 错误率>5%：需人工确认后恢复

#### SG-3 失败回退：评分体系失效

**场景**：评分与收益相关性低、优质钱包实际表现差、评分分布异常

**回退层级**：
1. **L1 - 参数回滚**：回退到上一个已知有效的参数版本
2. **L2 - 简化评分**：使用简化版评分（仅胜率和盈亏比两个维度）
3. **L3 - 人工评分**：暂停自动评分，进入人工审核模式
4. **L4 - 重新设计**：若连续3次调优失败，触发评分体系重设计

**恢复标准**：
- 参数回滚后相关性恢复≥0.6：继续使用回滚参数
- 简化评分有效：逐步增加维度，而非一次性启用全部维度
- 人工评分积累200个样本后：重新训练自动评分

#### SG-4 失败回退：过滤规则误杀

**场景**：误杀率>15%、优质钱包被大量过滤、机器人漏网

**回退层级**：
1. **L1 - 放宽阈值**：将所有硬过滤阈值放宽20%（如500→600笔）
2. **L2 - 白名单机制**：添加已知优质钱包白名单，绕过过滤
3. **L3 - 关闭激进规则**：关闭最激进的3条过滤规则，保留基础规则
4. **L4 - 人工审核**：所有过滤决策需人工确认

**恢复标准**：
- 误杀率<10%：逐步恢复关闭的规则，每次恢复1条，观察3天
- 新规则版本通过A/B测试：替换旧规则

#### SG-5 失败回退：回测策略亏损

**场景**：回测收益为负、夏普比率<0、最大回撤过大

**回退层级**：
1. **L1 - 保守策略**：切换到最保守策略（止损-30%，止盈2X卖50%）
2. **L2 - 降低仓位**：Fixed Buy降至0.5 SOL，Fixed Ratio降至5%
3. **L3 - 提高评分门槛**：只跟≥90分钱包（而非≥80分）
4. **L4 - 暂停跟单**：发现策略系统性失效，暂停所有跟单信号输出

**恢复标准**：
- 保守策略回测收益为正：逐步增加激进度
- 提高门槛后收益为正：逐步降低门槛，每次降5分
- 连续2周收益为正：恢复正常策略

#### SG-6 失败回退：验证闭环失效

**场景**：人工标注与系统评分严重不一致、自动调优越调越差

**回退层级**：
1. **L1 - 冻结自动调优**：停止自动参数调整，保持当前参数
2. **L2 - 扩大人工样本**：将人工标注样本从50扩大到200
3. **L3 - 简化评分模型**：使用线性加权替代复杂非线性计算
4. **L4 - 外部专家介入**：引入交易专家重新定义评分标准

**恢复标准**：
- 人工样本扩大后一致性>75%：恢复自动调优，但限制调整幅度
- 简化模型有效：在简化模型基础上逐步增加复杂度
- 专家确认：专家审核通过后，使用新评分标准

#### SG-7 失败回退：集成失败

**场景**：Dashboard集成冲突、与现有系统不兼容、性能问题

**回退层级**：
1. **L1 - 独立模块**：钱包发现层独立运行，不与Dashboard集成，通过CLI输出
2. **L2 - 简化集成**：仅提供API接口，不修改Dashboard UI
3. **L3 - 文件交换**：钱包发现层输出JSONL文件，Dashboard读取文件展示
4. **L4 - 完全独立**：两个系统独立运行，阶段2通过文件导入数据

**恢复标准**：
- 独立模块运行稳定1周：尝试重新集成
- 性能问题解决：逐步恢复完整集成

### 7.2 全局失败回退

**场景**：阶段1整体无法按时完成或质量不达标

**回退策略**：
1. **MVP回退**：仅实现SG-1（抓取）+ SG-3（简化评分，仅2个维度）+ SG-5（简化回测，1种策略），输出基础可跟单钱包列表
2. **时间回退**：阶段1延长2周，重点保证质量而非速度
3. **范围回退**：仅支持Solana链，放弃多链支持
4. **阶段回退**：阶段1不完全封闭，允许阶段2与阶段1并行迭代

## 9. 附录

### 9.1 术语表

| 术语 | 定义 |
|------|------|
| 聪明钱包 | 在链上交易中表现出高胜率、良好风控、稳定盈利的钱包地址 |
| 机器人识别 | 通过交易模式识别自动化操作钱包的过程 |
| 回测 | 使用历史数据模拟跟单策略，评估策略表现 |
| 夏普比率 | 超额收益/收益标准差，衡量风险调整后收益 |
| 索提诺比率 | 超额收益/下行收益标准差，仅惩罚下行波动 |
| 最大回撤 | 从峰值到谷底的最大亏损幅度 |
| 盈亏比 | 平均盈利金额 / 平均亏损金额 |
| 毕业代币 | 从Pump.fun迁移到Raydium等DEX的代币 |
| MEV | 最大可提取价值，通过交易排序获取的套利收益 |
| 滑点 | 实际成交价与预期价的偏差百分比 |
| 优先费 | 为加速交易处理额外支付的SOL费用 |

### 9.2 参考标准

| 指标 | 优质钱包标准 | 淘汰钱包标准 | 数据来源 |
|------|-------------|-------------|----------|
| 胜率 | ≥60% | <30% | 链上交易历史 |
| 每周交易 | 50-100笔 | >500笔或<5笔 | 链上交易历史 |
| 持仓周期 | ≥24小时 | <1小时 | 链上交易时间戳 |
| 投资回报 | 追求5x+ | 持续亏损 | 链上盈亏计算 |
| 单笔投资 | $500-$10K | >$20K或<$50 | 交易金额分析 |
| 总利润 | $30K-$100K | <0 | 链上盈亏计算 |
| 稳定币持有 | 有 | 无 | 当前余额分析 |
| 夏普比率 | ≥1.5 | <0 | 回测计算 |
| 最大回撤 | ≤40% | >65% | 回测计算 |
