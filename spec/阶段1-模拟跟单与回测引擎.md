## 1. 系统定位与边界

### 1.1 本阶段在整体路线图中的位置

```
整体路线图:
┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ 代币监控     │→│ 钱包发现     │→│ 模拟回测     │→│ 自动化跟单   │
│ (Phase 1-5)  │  │ (阶段1-A)    │  │ (阶段1-B)    │  │ (阶段2)      │
│   ✅ 完成    │  │   🔄 本阶段  │  │   🔄 本阶段  │  │   ⏳ 待设计  │
└──────────────┘  └──────────────┘  └──────────────┘  └──────────────┘
```

本阶段（阶段1-模拟跟单与回测引擎）包含两个子阶段：
- **子阶段 1-A（聪明钱包发现引擎）**：从链上数据或 GMGN 数据抓取中识别高质量聪明钱包，建立评分体系，输出候选钱包列表。
- **子阶段 1-B（模拟跟单回测引擎）**：对 1-A 输出的钱包进行历史交易模拟，验证跟单策略的盈亏表现，输出回测报告和参数调优建议。

### 1.2 安全边界（继承自 Phase 1-5）

| 规则 | 约束 |
|------|------|
| 无钱包签名 | 阶段1全程不引入私钥、签名或链上交易提交 |
| 无自动化执行 | 所有"交易"均为本地模拟，不调用任何执行端点 |
| 无 GMGN 账户操作 | 不访问 `~/.config/gmgn/.env`，不读取用户私钥配置 |
| 数据抓取限速 | 遵守 GMGN 数据抓取限速（2次/秒），内置限速器和退避策略 |
| 可追溯审计 | 所有钱包发现、评分、回测结果均持久化，支持事后复盘 |

### 1.3 与现有系统的集成点

| 现有系统 | 集成方式 |
|----------|----------|
| `gmgn_system_spec.md` | 继承数据字段定义（chain, token_address, detected_at 等） |
| `SCHEMA.md` | 复用 candidate input / scored output 结构，扩展 wallet 类型 |
| `gmgn_monitor/replay.py` | 复用 replay 机制，扩展为 wallet-scoring replay |
| `gmgn_monitor/doctor.py` | 扩展 doctor 检查，增加 wallet 发现引擎健康检查 |
| `gmgn_monitor/pipeline.py` | 扩展 pipeline 阶段，增加 wallet-discovery → backtest 流程 |
| `config/thresholds.json` | 扩展阈值配置，增加 wallet scoring 和 backtest 参数 |
| `gmgn_monitor/verify.py` | 扩展验证报告，包含 wallet 发现和回测子系统状态 |

## 2. 具体子目标（SMART 原则）

### 子目标 1-A-1：GMGN 数据抓取层（Data Fetcher）

| 属性 | 定义 |
|------|------|
| **Specific** | 实现 GMGN 前端数据抓取的限速 HTTP 客户端，覆盖钱包持仓列表、历史交易记录、代币统计三个端点。 |
| **Measurable** | 可抓取钱包数 ≥ 1000/批次，限速合规率 100%，成功率 ≥ 95%（含退避重试）。 |
| **Achievable** | 基于社区已知的 GMGN 前端接口格式和 IP 白名单机制，使用 Python requests + 限速装饰器实现。 |
| **Relevant** | 是后续钱包发现的数据基础；无数据则无法识别聪明钱包。 |
| **Time-bound** | 2 周内完成开发 + 测试。 |
| **验收标准** | ① `python3 -m gmgn_monitor.wallet_fetcher --batch-size 1000` 成功输出 JSONL；② 运行日志中无 429 以外的 HTTP 错误；③ 限速器日志显示平均 QPS ≤ 2.0。 |

### 子目标 1-A-2：聪明钱包评分引擎（Wallet Scorer）

| 属性 | 定义 |
|------|------|
| **Specific** | 基于给定筛选标准（胜率、交易频率、持仓周期、回报倍数），对抓取的原始钱包数据计算综合评分，输出 rank 列表。 |
| **Measurable** | 输出钱包 ≥ 500，评分 0-100 整数；覆盖胜率、PnL、持仓时长、交易频率、稳定币占比、机器人排除等 6 个维度。 |
| **Achievable** | 基于已知画像数据和链上交易解析逻辑，使用规则引擎 + 加权评分公式实现。 |
| **Relevant** | 是模拟跟单的对象选择基础；评分质量直接决定回测结果的可信度。 |
| **Time-bound** | 2 周内完成开发 + 单元测试。 |
| **验收标准** | ① `python3 -m gmgn_monitor.wallet_scorer --input data/raw_wallets.jsonl --output data/scored_wallets.jsonl` 成功运行；② 输出 JSONL 每行包含 `wallet_address`、`score`、`tier`、`decision`、`reasons`、`metrics` 字段；③ 单元测试覆盖 6 个维度评分逻辑，覆盖率 ≥ 80%。 |

### 子目标 1-A-3：优质钱包画像验证（Profile Validator）

| 属性 | 定义 |
|------|------|
| **Specific** | 建立可配置的优质钱包画像规则，自动标记符合画像的钱包，排除机器人钱包。 |
| **Measurable** | 画像匹配率 ≥ 80%（与人工抽查 100 个钱包对比）；机器人误排除率 ≤ 5%。 |
| **Achievable** | 使用已知规则（胜率>60%、每周50-100笔、持仓>24h、单笔$500-$10K、利润$30K-$100K、7天交易<500次）作为初始规则。 |
| **Relevant** | 防止机器人钱包污染回测样本，确保跟单目标的质量。 |
| **Time-bound** | 1 周。 |
| **验收标准** | ① `config/wallet_profiles.json` 存在且可被 scorer 加载；② 包含 `smart_wallet`、`bot_wallet` 两个规则集；③ 单元测试验证机器人钱包被正确排除。 |

### 子目标 1-B-1：模拟跟单交易引擎（Paper Trading Engine）

| 属性 | 定义 |
|------|------|
| **Specific** | 实现一个纯本地模拟交易引擎，对钱包历史交易进行"假设跟随"模拟，支持三种买入模式和标准止盈止损规则。 |
| **Measurable** | 支持市价单模拟；支持三种买入模式（Max Buy、Fixed Buy 0.5-1 SOL/笔、Fixed Ratio）；支持标准止盈止损（+100%卖50%、+300%卖剩余50%、-65%全卖）；可输出每笔模拟交易的完整生命周期。 |
| **Achievable** | 基于已知 GMGN 交易模式和时间序列数据，使用本地状态机模拟订单执行。 |
| **Relevant** | 是验证跟单策略是否可行的核心；无回测则无法证明策略有效性。 |
| **Time-bound** | 3 周。 |
| **验收标准** | ① `python3 -m gmgn_monitor.paper_trade --wallet <address> --mode fixed_buy --amount 1.0` 输出模拟交易 JSONL；② 输出包含 entry_price、exit_price、pnl_percent、holding_duration、fees、slippage 等字段；③ 单元测试覆盖三种买入模式 + 止盈止损触发逻辑。 |

### 子目标 1-B-2：回测报告生成器（Backtest Reporter）

| 属性 | 定义 |
|------|------|
| **Specific** | 基于模拟交易结果，生成包含盈亏统计、夏普比率、最大回撤、胜率、盈亏比、手续费损耗分析的 Markdown 回测报告。 |
| **Measurable** | 报告包含：总收益率、年化收益率、最大回撤、夏普比率、胜率、盈亏比、平均持仓时间、手续费占比、滑点损耗、优先费损耗；至少覆盖 30 天模拟周期。 |
| **Achievable** | 使用 pandas 做时间序列聚合，已知费率模型（1% 手续费、20-50% 滑点、0.01-0.1 SOL 优先费）。 |
| **Relevant** | 是决策是否进入阶段2（自动化）的关键依据；回测必须证明正期望值。 |
| **Time-bound** | 2 周。 |
| **验收标准** | ① `python3 -m gmgn_monitor.backtest_report --input data/paper_trades.jsonl --output data/backtest_report.md` 成功运行；② 报告包含完整的回测统计和图表占位区；③ 输出包含 `expectancy_per_trade` 和 `expectancy_after_costs` 字段；④ 回测通过必须满足 `expectancy_after_costs > 0`。 |

### 子目标 1-B-3：参数调优与策略搜索（Strategy Optimizer）

| 属性 | 定义 |
|------|------|
| **Specific** | 对止盈止损比例、滑点设置、买入模式、持仓周期等参数进行网格搜索，找出历史最优参数组合。 |
| **Measurable** | 搜索空间覆盖至少 3 个维度（止盈比例、止损比例、买入模式），每个维度至少 3 个值；输出最优 3 组参数及对应回测指标。 |
| **Achievable** | 使用简单的多进程网格搜索，避免复杂优化算法。 |
| **Relevant** | 防止过拟合；网格搜索 + 交叉验证（walk-forward）是标准做法。 |
| **Time-bound** | 2 周。 |
| **验收标准** | ① `python3 -m gmgn_monitor.strategy_optimizer --grid-search config/optimizer_grid.json` 成功运行；② 输出最优参数组合和对应的回测结果；③ 包含 walk-forward 验证（至少 2 个时间窗口）以防过拟合。 |

## 3. 输入/输出数据模型

### 3.1 新数据模型总览

```
原始数据层:
  RawWallet  →  RawTrade  →  RawTokenStat
     ↓              ↓              ↓
评分层:
  ScoredWallet → WalletProfile → WalletTier
     ↓
模拟交易层:
  PaperTrade  →  TradeLifecycle  →  PositionLog
     ↓
回测层:
  BacktestResult  →  PerformanceMetrics  →  StrategyReport
```

### 3.2 字段定义详表

#### 3.2.1 RawWallet（原始钱包数据）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `wallet_address` | string | 非空，Solana base58 地址 | 钱包地址 |
| `chain` | string | 枚举: `solana` | 当前仅支持 Solana |
| `first_seen_at` | ISO timestamp | 有效日期 | 首次发现时间 |
| `last_active_at` | ISO timestamp | 有效日期，≥ first_seen_at | 最后活跃时间 |
| `total_trades_7d` | integer | 0-1000 | 近7天交易笔数 |
| `total_trades_30d` | integer | ≥ 0 | 近30天交易笔数 |
| `winning_trades_30d` | integer | ≥ 0，≤ total_trades_30d | 近30天盈利笔数 |
| `win_rate_30d` | number | 0-100，保留2位小数 | 胜率 |
| `avg_investment_usd` | number | ≥ 0 | 平均单笔投资额（USD） |
| `avg_profit_usd` | number | ≥ 0 | 平均单笔利润（USD） |
| `total_profit_usd` | number | 可为负 | 近30天总利润（USD） |
| `avg_holding_duration_hours` | number | ≥ 0 | 平均持仓时长（小时） |
| `stablecoin_balance_usd` | number | ≥ 0 | 稳定币持仓余额（USD） |
| `portfolio_balance_usd` | number | ≥ 0 | 总 portfolio 余额（USD） |
| `source` | string | 非空 | 数据来源，如 `gmgn_fetcher` |
| `fetched_at` | ISO timestamp | 有效日期 | 抓取时间 |

#### 3.2.2 ScoredWallet（评分后钱包数据）

继承 RawWallet 所有字段，新增：

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `score` | integer | 0-100 | 综合评分 |
| `tier` | string | 枚举: `S`/`A`/`B`/`C`/`D` | 等级：S(90-100)、A(75-89)、B(60-74)、C(40-59)、D(<40) |
| `decision` | string | 枚举: `follow`/`watch`/`reject` | 决策：follow=可跟单，watch=持续观察，reject=排除 |
| `reasons` | array[string] | 有序列表 | 评分理由，如 `["胜率62%>60%", "平均持仓28h>24h", "机器人排除: 7天交易87笔<500"]` |
| `metrics` | object | 非空 | 子评分明细，见下方 |
| `profile_matched` | string | 枚举: `smart_wallet`/`bot_wallet`/`unknown` | 画像匹配结果 |

**metrics 子对象结构：**

```json
{
  "win_rate_score": 18,        // 0-20，胜率权重
  "profit_score": 20,          // 0-20，利润权重
  "frequency_score": 15,       // 0-20，交易频率权重
  "holding_score": 15,         // 0-15，持仓周期权重
  "stability_score": 10,       // 0-15，稳定币/余额稳定性
  "consistency_score": 12,     // 0-10，一致性/夏普
  "total": 90                  // 总分
}
```

#### 3.2.3 WalletProfile（画像规则配置）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `profile_name` | string | 非空，如 `smart_wallet` | 画像名称 |
| `description` | string | 非空 | 画像描述 |
| `rules` | array[object] | 至少1条 | 规则列表 |
| `rules[].field` | string | 非空 | 字段名 |
| `rules[].operator` | string | 枚举: `gt`/`gte`/`lt`/`lte`/`eq`/`in`/`between` | 比较符 |
| `rules[].value` | number/array | 与 operator 匹配 | 阈值 |
| `rules[].weight` | number | 0-1 | 该规则在匹配度中的权重 |
| `exclude_if_match` | boolean | 默认 false | 是否排除（用于机器人规则） |
| `min_match_ratio` | number | 0-1 | 最低匹配比例（综合 ≥ 此值才视为匹配） |

**标准画像规则示例（smart_wallet）：**

```json
{
  "profile_name": "smart_wallet",
  "description": "优质聪明钱包画像：高胜率、适中频率、合理持仓周期",
  "rules": [
    {"field": "win_rate_30d", "operator": "gte", "value": 60, "weight": 0.20},
    {"field": "total_trades_7d", "operator": "between", "value": [50, 100], "weight": 0.15},
    {"field": "avg_holding_duration_hours", "operator": "gte", "value": 24, "weight": 0.15},
    {"field": "avg_investment_usd", "operator": "between", "value": [500, 10000], "weight": 0.10},
    {"field": "avg_profit_usd", "operator": "between", "value": [30000, 100000], "weight": 0.15},
    {"field": "total_trades_7d", "operator": "lt", "value": 500, "weight": 0.15},
    {"field": "stablecoin_balance_usd", "operator": "gt", "value": 0, "weight": 0.10}
  ],
  "exclude_if_match": false,
  "min_match_ratio": 0.70
}
```

**机器人排除画像（bot_wallet）：**

```json
{
  "profile_name": "bot_wallet",
  "description": "高频机器人钱包排除规则",
  "rules": [
    {"field": "total_trades_7d", "operator": "gte", "value": 500, "weight": 0.50},
    {"field": "avg_holding_duration_hours", "operator": "lt", "value": 0.5, "weight": 0.30},
    {"field": "win_rate_30d", "operator": "gte", "value": 95, "weight": 0.20}
  ],
  "exclude_if_match": true,
  "min_match_ratio": 0.60
}
```

#### 3.2.4 PaperTrade（模拟交易记录）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `trade_id` | string | UUID 格式 | 唯一交易ID |

| `token_address` | string | 非空 | 代币合约地址 |

| `entry_amount_sol` | number | > 0 | 入场金额（SOL） |
| `entry_at` | ISO timestamp | 有效日期 | 入场时间 |
| `exit_price` | number | > 0 或 null | 出场价格（USD） |
| `exit_amount_usd` | number | > 0 或 null | 出场金额（USD） |
| `exit_at` | ISO timestamp | 有效日期或 null | 出场时间 |
| `pnl_percent` | number | 可为负 | 盈亏百分比（扣除费用前） |
| `pnl_after_costs_percent` | number | 可为负 | 扣除费用后盈亏百分比 |
| `realized_pnl_usd` | number | 可为负 | 已实现盈亏（USD） |
| `holding_duration_minutes` | number | ≥ 0 或 null | 持仓时长（分钟） |
| `status` | string | 枚举: `open`/`closed`/`stopped`/`liquidated` | 交易状态 |
| `close_reason` | string | 枚举: `tp_50`/`tp_100`/`sl`/`manual`/`expired` | 平仓原因 |
| `fees_usd` | number | ≥ 0 | 交易手续费（1%） |
| `slippage_percent` | number | ≥ 0 | 滑点百分比（20-50%） |
| `priority_fee_sol` | number | ≥ 0 | 优先费（SOL） |
| `total_costs_usd` | number | ≥ 0 | 总费用（USD） |
| `tp_levels` | array[object] | 非空 | 止盈层级记录 |
| `tp_levels[].level` | number | 正整数 | 第几级止盈 |
| `tp_levels[].trigger_percent` | number | > 0 | 触发百分比 |
| `tp_levels[].sell_percent` | number | 0-100 | 卖出仓位比例 |
| `tp_levels[].executed` | boolean | — | 是否已执行 |
| `tp_levels[].executed_at` | ISO timestamp | 或 null | 执行时间 |
| `sl_level` | object | 非空 | 止损记录 |
| `sl_level.trigger_percent` | number | 负数 | 止损触发百分比 |
| `sl_level.sell_percent` | number | 100 | 全卖 |
| `sl_level.executed` | boolean | — | 是否已执行 |
| `sl_level.executed_at` | ISO timestamp | 或 null | 执行时间 |
| `backtest_batch_id` | string | UUID | 所属回测批次 |
| `created_at` | ISO timestamp | 有效日期 | 记录创建时间 |

**标准止盈止损配置（默认）：**

```json
  ],
  "stop_loss": {
    "trigger_percent": -65,

  }

```

**保守止盈止损配置（可选）：**

```json

  "take_profit": [
    {"level": 1, "trigger_percent": 100, "sell_percent": 50},
    {"level": 2, "trigger_percent": 200, "sell_percent": 30},
    {"level": 3, "trigger_percent": 500, "sell_percent": 20}

  }
```

#### 3.2.5 BacktestResult（回测结果）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `backtest_id` | string | UUID | 回测批次ID |
| `wallet_address` | string | 非空 | 目标钱包地址 |
| `strategy_config` | object | 非空 | 策略配置快照（止盈止损、买入模式、滑点等） |
| `period_start` | ISO timestamp | 有效日期 | 回测起始时间 |
| `period_end` | ISO timestamp | 有效日期 | 回测结束时间 |
| `total_trades` | integer | ≥ 0 | 总交易数 |
| `winning_trades` | integer | ≥ 0 | 盈利交易数 |
| `losing_trades` | integer | ≥ 0 | 亏损交易数 |
| `win_rate` | number | 0-100 | 胜率 |

## 4. 算法/逻辑设计

### 4.1 聪明钱包评分公式

#### 4.1.1 多维度评分模型

总分 = min(100, 各维度得分之和)

| 维度 | 权重 | 满分 | 计算公式 | 数据来源 |
|------|------|------|----------|----------|
| 胜率 | 20% | 20 | `win_rate_score = min(20, (win_rate_30d / 80) * 20)` | 原始交易统计 |
| 利润 | 20% | 20 | `profit_score = min(20, log10(1 + total_profit_usd / 10000) * 4)` | 原始交易统计 |
| 交易频率 | 20% | 20 | `frequency_score = 20 * (1 - abs(optimal - actual) / optimal)`，optimal=75笔/周 | 原始交易统计 |
| 持仓周期 | 15% | 15 | `holding_score = min(15, avg_holding_duration_hours / 48 * 15)` | 原始交易统计 |
| 稳定性 | 15% | 15 | `stability_score = min(15, stablecoin_ratio * 15)`，ratio = stablecoin_balance / portfolio_balance | 当前持仓快照 |
| 一致性 | 10% | 10 | `consistency_score = min(10, sharpe_proxy * 10)`，sharpe_proxy = avg_profit_usd / std_dev_profit_usd | 原始交易统计 |

#### 4.1.2 频率评分细节（避免机器人/低频）

```python
def frequency_score(trades_7d: int) -> float:
    """
    最优频率: 50-100 笔/周（约 7-14 笔/天）。
    < 30 笔/周: 频率过低，可能样本不足或不够活跃
    > 200 笔/周: 频率过高，可能是机器人或过度交易
    > 500 笔/周: 直接排除（机器人）
    """
    if trades_7d >= 500:
        return 0  # 机器人排除
    
    optimal = 75  # 最优值
    max_deviation = 125  # 从最优到边界的最大偏差（75-(-50) 或 200-75）
    
    if trades_7d < 30:
        deviation = 30 - trades_7d  # 低频偏差
    else:
        deviation = abs(trades_7d - optimal)
    
    score = 20 * max(0, 1 - deviation / max_deviation)
    return round(score, 1)
```

#### 4.1.3 画像匹配度

```python
def profile_match(wallet: RawWallet, profile: WalletProfile) -> dict:
    """
    计算钱包与画像的匹配度。
    返回: {match_ratio: float, matched_rules: list, excluded: bool}
    """
    match_scores = []
    matched_rules = []
    
    for rule in profile.rules:
        field_value = getattr(wallet, rule.field)
        matched = evaluate_rule(field_value, rule.operator, rule.value)
        match_scores.append(rule.weight if matched else 0)
        if matched:
            matched_rules.append(rule.field)
    
    total_weight = sum(r.weight for r in profile.rules)
    match_ratio = sum(match_scores) / total_weight if total_weight > 0 else 0
    excluded = profile.exclude_if_match and match_ratio >= profile.min_match_ratio
    
    return {
        "match_ratio": round(match_ratio, 2),
        "matched_rules": matched_rules,
        "excluded": excluded
    }
```

#### 4.2.2 止盈止损触发逻辑（状态机）

```python
class TradeLifecycle:
    """
    模拟交易的生命周期状态机。
    """
    
    def __init__(self, paper_trade: PaperTrade):
        self.trade = paper_trade
        self.remaining_position = 100.0  # 剩余仓位百分比
        self.status = "open"
    
    def update_price(self, current_price: float, current_time: datetime):
        """
        根据当前价格更新交易状态，检查止盈止损触发。
        """
        if self.status != "open":
            return
        
        pnl_percent = (current_price - self.trade.entry_price) / self.trade.entry_price * 100
        
        # 检查止盈层级（按顺序）
        for tp in self.trade.tp_levels:
            if not tp.executed and pnl_percent >= tp.trigger_percent:
                self._execute_tp(tp, current_price, current_time)
        
        # 检查止损（全仓卖出）
        if self.trade.sl_level and not self.trade.sl_level.executed:
            if pnl_percent <= self.trade.sl_level.trigger_percent:
                self._execute_sl(current_price, current_time)
        
        # 检查是否全部平仓
        if self.remaining_position <= 0:
            self.status = "closed"
    
    def _execute_tp(self, tp, price, time):
        sell_amount = self.trade.entry_amount_usd * (tp.sell_percent / 100)
        self.remaining_position -= tp.sell_percent
        tp.executed = True
        tp.executed_at = time
        # 记录部分卖出...
    
    def _execute_sl(self, price, time):
        self.remaining_position = 0
        self.trade.sl_level.executed = True
        self.trade.sl_level.executed_at = time
        self.status = "stopped"
        self.trade.close_reason = "sl"
```

```python
class CostModel:
    """
    模拟交易费用计算。
    参考已知费率：1% 交易费、20-50% 滑点、0.01-0.1 SOL 优先费。
    """
    
    def __init__(self, config: dict):
        self.trading_fee_percent = config.get("trading_fee_percent", 1.0)  # 1%
        self.slippage_percent = config.get("slippage_percent", 25.0)  # 默认 25%（中位数）
        self.priority_fee_sol = config.get("priority_fee_sol", 0.02)  # 默认 0.02 SOL
        self.sol_price_usd = config.get("sol_price_usd", 150)
    
    def calculate_entry_costs(self, amount_usd: float) -> dict:
        fee = amount_usd * self.trading_fee_percent / 100
        slippage = amount_usd * self.slippage_percent / 100
        priority_fee_usd = self.priority_fee_sol * self.sol_price_usd
        
        return {
            "fee_usd": fee,
            "slippage_usd": slippage,
            "priority_fee_usd": priority_fee_usd,
            "total_costs_usd": fee + slippage + priority_fee_usd,
            "effective_entry_amount": amount_usd - fee - slippage - priority_fee_usd
        }
    
    def calculate_exit_costs(self, amount_usd: float) -> dict:
        # 出场同样有费用和滑点
        return self.calculate_entry_costs(amount_usd)
```

### 4.3 回测策略逻辑

#### 4.3.1 Walk-Forward 回测（防过拟合）

```python
def walk_forward_backtest(wallets: list, 
                          price_data: dict,  # token_address -> time series
                          train_window_days: int = 14,
                          test_window_days: int = 7,
                          strategy_config: dict) -> list:
    """
    滑动窗口 Walk-Forward 回测：
    - 用前 14 天数据训练（选择最优参数或钱包组合）
    - 用后 7 天数据测试（验证泛化能力）
    - 窗口滑动，重复 N 次
    """
    results = []
    start = min(pd.to_datetime(t) for t in price_data.values())
    end = max(pd.to_datetime(t) for t in price_data.values())
    
    current = start
    while current + timedelta(days=train_window_days + test_window_days) <= end:
        train_end = current + timedelta(days=train_window_days)
        test_end = train_end + timedelta(days=test_window_days)
        
        # 训练期：选择最优钱包参数
        train_data = slice_data(price_data, current, train_end)
        best_params = optimize_params(wallets, train_data, strategy_config)
        
        # 测试期：用训练期参数验证
        test_data = slice_data(price_data, train_end, test_end)
        test_result = run_backtest(wallets, test_data, best_params)
        
        results.append({
            "train_period": (current, train_end),
            "test_period": (train_end, test_end),
            "params": best_params,
            "result": test_result
        })
        
        current += timedelta(days=test_window_days)  # 滑动窗口
    
    return results
```

#### 4.3.2 参数网格搜索

```python
def grid_search(wallets, price_data, grid_config) -> list:
    """
    网格搜索最优策略参数。
    搜索维度示例：止盈比例、止损比例、买入模式、滑点设置。
    """
    param_space = {
        "tp_level_1": [50, 100, 150],      # 第一级止盈触发点
        "tp_level_2": [200, 300, 500],     # 第二级止盈触发点
        "sl_percent": [-30, -40, -65],     # 止损比例
        "buy_mode": ["fixed_buy", "fixed_ratio"],
        "slippage": [20, 30, 50]           # 滑点假设
    }
    
    results = []
    for params in itertools.product(*param_space.values()):
        param_dict = dict(zip(param_space.keys(), params))
        backtest_result = run_backtest(wallets, price_data, param_dict)
        results.append({
            "params": param_dict,
            "expectancy_after_costs": backtest_result.expectancy_after_costs_percent,
            "sharpe": backtest_result.sharpe_ratio,
            "max_drawdown": backtest_result.max_drawdown_percent
        })
    
    # 排序：优先期望值为正，然后夏普比率，最后回撤最小
    results.sort(key=lambda x: (
        x["expectancy_after_costs"] > 0,  # 正值优先
        x["expectancy_after_costs"],      # 越高越好
        x["sharpe"],                      # 越高越好
        abs(x["max_drawdown"])            # 越小越好
    ), reverse=True)
    
    return results[:10]  # 返回前10
```

| 1-B-1 | 模拟交易 | 三种买入模式输出正确 | `python3 -m gmgn_monitor.paper_trade --mode fixed_buy` |
| 1-B-1 | 止盈止损 | 触发逻辑正确 | 单元测试 `test_tp_sl_trigger` |
| 1-B-2 | 回测报告 | 包含所有必需指标 | `python3 -m gmgn_monitor.backtest_report` |
| 1-B-2 | 期望值 | `expectancy_after_costs > 0` | 检查报告字段 |
| 1-B-3 | 网格搜索 | 输出最优 3 组参数 | `python3 -m gmgn_monitor.strategy_optimizer` |
| 1-B-3 | Walk-Forward | 至少 2 个窗口验证 | 检查输出 `walk_forward_results` |
| 全局 | 安全扫描 | 无签名/私钥/交易代码 | `python3 -m gmgn_monitor.doctor` |
| 全局 | 集成测试 | Pipeline 端到端通过 | `python3 -m gmgn_monitor.pipeline` |

### 6.2 阶段1整体验收（Go/No-Go 决策）

**阶段1 通过必须满足：**

1. **数据质量**：成功抓取 ≥ 1000 个钱包，评分引擎输出 ≥ 500 个有效钱包。
2. **评分质量**：S+A 等级钱包占比 ≥ 10%（约 50 个），且人工抽查准确率 ≥ 80%。
3. **模拟回测**：至少对 Top 20 钱包进行 30 天模拟回测，生成完整回测报告。
4. **策略有效性**：至少有一组参数满足 `expectancy_after_costs > 0`（正期望值）。
5. **过拟合检验**：Walk-Forward 验证通过，训练集与测试集表现差异 ≤ 30%。
6. **安全合规**：`doctor.py` 安全扫描 100% 通过，无签名/私钥/交易代码。
7. **Loop 闭合**：5 个反馈循环至少运行过一次，记录保存在 `data/feedback/`。

**Go/No-Go 决策流程：**

```
所有验收项通过 → Go → 进入阶段2（自动化跟单）设计
任意验收项失败 → No-Go → 分析失败原因 → 调整参数/算法 → 重新测试
```

## 7. 失败回退策略

### 7.1 按失败类型分类的回退策略

#### 7.1.1 数据抓取失败（子目标 1-A-1）

| 失败场景 | 回退策略 | 责任人 | 时间窗口 |
|----------|----------|--------|----------|
| GMGN 前端接口变更 | 切换到备用数据源（社区 API、DEX Screener、手动 fixture） | 系统 | 1 天 |
| IP 被封禁 | 降低 QPS 至 1次/秒，增加退避时间（指数退避） | 系统 | 自动 |
| 数据质量下降（字段缺失） | 使用保守默认值，标记为不完整，不纳入评分 | 系统 | 自动 |
| 抓取成功率 < 80% | 暂停自动抓取，切换到手动 fixture 模式，告警通知 | 系统 | 自动 |
| 连续 3 天无数据 | 暂停钱包发现阶段，维持现有评分列表，触发人工介入 | 系统 + 人工 | 即时 |

#### 7.1.2 评分引擎失败（子目标 1-A-2）

| 失败场景 | 回退策略 | 责任人 | 时间窗口 |
|----------|----------|--------|----------|
| 评分公式产生极端值（>100 或 <0） | 截断到 [0, 100]，记录异常日志，触发检查 | 系统 | 自动 |
| 机器人误排除率 > 10% | 放宽机器人规则（7天交易阈值从 500 调到 800），人工复查 | 系统 + 人工 | 1 天 |
| 优质钱包漏检率 > 20% | 降低画像匹配阈值（从 0.70 调到 0.60），增加观察列表 | 系统 | 1 天 |
| 评分分布异常（全部集中在某等级） | 检查权重配置，增加区分度指标，重新校准 | 人工 | 2 天 |

#### 7.1.3 模拟回测失败（子目标 1-B-1/2）

| 失败场景 | 回退策略 | 责任人 | 时间窗口 |
|----------|----------|--------|----------|
| 回测期望值为负（所有参数） | 拒绝进入阶段2，返回阶段1-A 优化钱包选择；增加保守止盈 | 系统 + 人工 | 3 天 |
| 历史价格数据缺失 | 使用最近可获取价格作为近似，标记数据质量；或缩小回测窗口 | 系统 | 自动 |
| 费用模型导致全部亏损 | 降低滑点假设（从 50% 到 20%），或使用实际观察数据校准 | 人工 | 2 天 |
| 回测报告生成失败 | 使用简化模板，输出关键指标 CSV，跳过图表 | 系统 | 自动 |
| 连续 3 个回测批次负收益 | 暂停所有策略推荐，触发系统告警，要求人工审查 | 系统 | 即时 |

#### 7.1.4 过拟合/参数失效（子目标 1-B-3）

| 失败场景 | 回退策略 | 责任人 | 时间窗口 |
|----------|----------|--------|----------|
| 训练集 vs 测试集差异 > 50% | 增加正则化：缩小搜索空间、增加最小交易次数约束 | 系统 | 1 天 |
| 最优参数在实际中失效 | 使用次优但更稳健的参数（夏普比率最高的，而非收益最高的） | 人工 | 2 天 |
| 网格搜索计算量过大 | 减少搜索维度（从 4 维降到 2 维），使用随机搜索替代 | 系统 | 自动 |
| 市场环境剧变（如大暴跌） | 暂停策略更新，使用防御性参数（ tighter 止损），人工评估 | 人工 | 即时 |

### 7.2 全局回退开关（Kill Switch）

即使阶段1 是模拟阶段，也需要全局回退机制：

```python
# config/kill_switch.json
{
    "enabled": false,  # 手动触发
    "triggers": {
        "max_consecutive_negative_expectancy": 3,
        "max_drawdown_percent": -50,
        "min_win_rate_percent": 30,
        "max_bot_false_positive_rate": 0.15
    },
    "actions": {
        "pause_wallet_discovery": true,
        "pause_backtest": true,
        "clear_candidate_queue": false,
        "notify_operator": true,
        "require_manual_review": true
    }
}
```

**Kill Switch 触发条件：**
- 连续 3 个回测批次期望值为负
- 回测最大回撤超过 50%
- 模拟胜率低于 30%
- 机器人误排除率超过 15%

**触发后动作：**
1. 暂停钱包发现引擎
2. 暂停模拟回测引擎
3. 保留现有数据，不清空队列
4. 向操作员发送告警（Telegram dry-run / 日志）
5. 要求人工审查后方可恢复

## 9. 风险与已知约束

### 9.1 数据约束

| 约束 | 说明 | 缓解措施 |
|------|------|----------|
| GMGN 无官方 API | 数据来自前端抓取，结构可能变更 | ① 内置版本检测，结构不匹配时告警；② 维护多个版本适配器；③ 备用数据源（社区 API、手动 fixture） |
| 限速 2次/秒 | 大规模抓取耗时 | ① 限速器内置；② 批量任务可分解到多个时间窗口；③ 优先使用已有数据而非实时抓取 |
| 历史数据不完整 | 链上数据可能缺失早期记录 | ① 使用可获取的最长窗口；② 标记数据质量；③ 小样本钱包使用更保守评分 |
| Pump.fun 高归零率 | 98.6% 未毕业即归零 | ① 模拟交易包含归零场景；② 费用模型包含极端滑点；③ 回测期望值为负时拒绝策略 |
| 前100名 vs 后续参与者 | 前100获利 300%，后续亏损 82% | ① 模拟延迟入场（非第一时间跟单）；② 测试不同延迟策略；③ 回测包含入场时机敏感性分析 |

### 9.2 模型约束

| 约束 | 说明 | 缓解措施 |
|------|------|----------|
| 过拟合风险 | 历史最优参数可能在未来失效 | ① Walk-Forward 验证；② 使用次优稳健参数；③ 限制参数搜索空间；④ 定期重校准 |
| 幸存者偏差 | 只看到现在还活跃的钱包 | ① 尝试获取已退出钱包数据；② 标记数据时间范围；③ 保守估计表现 |
| 费用模型不准确 | 实际费用可能与模拟不同 | ① 使用保守高估计（50% 滑点）；② 与真实交易对比校准；③ 定期更新费用参数 |
| 市场环境变化 | 牛市/熊市策略表现不同 | ① 分市场环境回测；② 使用防御性参数作为默认；③ 监控策略表现退化 |

## 10. 附录

### 10.1 术语表

| 术语 | 定义 |
|------|------|
| 聪明钱包 (Smart Wallet) | 在链上交易表现持续优于平均、有明确盈利策略的钱包地址 |
| 机器人钱包 (Bot Wallet) | 使用自动化脚本高频交易的钱包，通常 7 天交易 > 500 次 |
| 跟单 (Copy Trading) | 跟踪聪明钱包的买入/卖出行为，并在其后执行相同操作 |
| 模拟跟单 (Paper Trading) | 不实际执行交易，仅在本地记录假设交易的结果 |
| 回测 (Backtest) | 使用历史数据验证策略在过去的表现 |
| Walk-Forward | 滑动窗口训练/测试方法，用于防止过拟合 |
| 期望值 (Expectancy) | 每笔交易的平均预期收益，正期望值意味着长期盈利 |
| 夏普比率 (Sharpe Ratio) | 风险调整后的收益指标，值越高越好 |
| 滑点 (Slippage) | 预期成交价格与实际成交价格之间的差异 |
| 优先费 (Priority Fee) | Solana 上加速交易确认的费用 |
| 止盈止损 (TP/SL) | 预设的盈利卖出点（Take Profit）和亏损止损点（Stop Loss） |
| 分批止盈 (Laddered Exit) | 在不同价格水平分批卖出，而非一次性清仓 |
| MEV 防护 | 防止矿工/验证者提取价值的交易保护机制 |
| Pump.fun | Solana 上的 memecoin 发行平台，毕业率极低 |
| 毕业 (Graduate) | Pump.fun 代币从 bonding curve 进入 Raydium DEX 的过程 |
