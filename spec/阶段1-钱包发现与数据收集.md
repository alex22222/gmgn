# 阶段1：钱包发现与数据收集 — 详细实现规范

> **版本**: v1.0  
> **日期**: 2026-06-16  
> **阶段**: 阶段1（发现 + 模拟回测）  
> **目标**: 建立高质量聪明钱包的自动化发现、评分、回测体系，为阶段2（自动化跟单）输出经过验证的钱包白名单与策略参数。

---

## 1. 阶段1 子目标分解（SMART 原则）

阶段1 被分解为 **6 个可量化、可验收的子目标**。每个子目标均包含：
- **S**pecific（具体做什么）
- **M**easurable（可量化的指标）
- **A**chievable（技术可行）
- **R**elevant（与阶段2相关）
- **T**ime-bound（可估算工作量）

---

### 子目标 1.1：数据抓取基础设施（Data Pipeline）

**Specific**: 构建稳定、限速、可重试的 GMGN 数据抓取管道，能够持续获取链上钱包和代币交易数据。

**Measurable**:
- 抓取成功率 ≥ 95%（排除网络超时和GMGN服务不可用）
- 请求速率严格限制在 2 次/秒以内，且具备自适应降速能力
- 支持断点续传：任何中断后可从上次成功位置恢复
- 原始数据存储完备性：100% 请求响应 JSON 完整落盘（含时间戳和请求元数据）

**Achievable**: 利用社区 GmGnAPI（Python WebSocket）和官方 gmgn-cli（npm）作为基础，加上限速队列和重试机制即可实现。

**Relevant**: 所有后续子目标都依赖稳定的数据源。

**Time-bound**: 2 个工作日内完成基础设施搭建和验证。

---

### 子目标 1.2：钱包候选池构建（Candidate Pool）

**Specific**: 从 GMGN 数据中筛选出初步符合"聪明钱包"画像的候选地址池，建立基础过滤机制。

**Measurable**:
- 候选池规模：至少 5,000 个活跃地址（过去 30 天有 ≥10 笔交易）
- 基础过滤后淘汰率 ≥ 80%（即原始数据 25,000+ 地址 → 候选池 5,000）
- 过滤规则覆盖：交易频率、最低利润、持仓周期、单笔投资额
- 候选池数据新鲜度：每 24 小时自动更新一次

**Achievable**: 基于已知数据画像（胜率>60%、每周50-100笔、持仓>24h、利润$30K-$100K）设计 SQL 过滤即可。

**Relevant**: 为评分体系提供高质量输入，避免将机器人或新手钱包纳入评分。

**Time-bound**: 与 1.1 并行开发，基础设施完成后 1 个工作日内完成过滤逻辑。

---

### 子目标 1.3：多维度评分引擎（Scoring Engine）

**Specific**: 设计并实现一个综合评分算法，对候选钱包进行多维度打分，输出可排序的推荐列表。

**Measurable**:
- 评分维度 ≥ 5 个（收益率、胜率、风险控制、一致性、活跃度）
- 每个维度权重可调，支持配置文件热加载
- 评分输出范围：0-100，保留两位小数
- 评分计算延迟：单钱包 ≤ 50ms（批处理 ≥ 100 钱包/秒）
- 评分与人工标注的 Top 100 钱包重叠率 ≥ 70%（验证集测试）

**Achievable**: 基于已知公式和维度设计加权评分系统，使用 Python 实现。

**Relevant**: 阶段2的跟单白名单直接来源于评分引擎的 Top N 输出。

**Time-bound**: 3 个工作日完成算法设计、实现和初步验证。

---

### 子目标 1.4：历史回测模拟（Backtesting）

**Specific**: 对评分高的钱包进行历史交易模拟回测，验证"如果跟单该钱包，实际收益如何"。

**Measurable**:
- 回测覆盖：至少 Top 100 评分钱包的完整历史交易（过去 90 天）
- 回测策略：支持三种买入模式（Max Buy、Fixed Buy 0.5-1 SOL、Fixed Ratio）
- 回测策略：支持标准止盈止损（+100%卖50%，+300%卖剩余50%，止损-65%）和保守/激进两种策略
- 输出指标：累计收益率、最大回撤、夏普比率、胜率、盈亏比、交易次数
- 回测与真实跟单收益偏差 ≤ 15%（假设滑点和手续费模型准确）

**Achievable**: 基于 GMGN 历史交易数据，按时间顺序模拟执行。

**Relevant**: 回测结果是决定是否将该钱包纳入阶段2跟单白名单的核心依据。

**Time-bound**: 4 个工作日完成回测框架 + 至少 100 个钱包的回测执行。

---

### 子目标 1.5：质量监控与反馈循环（Loop Engineering）

**Specific**: 建立 5 个自我修正的反馈循环，持续验证数据质量、评分准确性和回测有效性，自动调整参数。

**Measurable**:
- 5 个 Loop 全部部署，每个 Loop 有明确的触发条件、执行动作和日志记录
- Loop 1（数据质量）：检测到异常数据时自动告警并触发重抓，异常数据率 < 1%
- Loop 2（评分校验）：Top 20 钱包的评分分布每周变化幅度 ≤ 15%，剧烈变化时触发权重审查
- Loop 3（回测校准）：回测结果与实时模拟跟踪的 7 日偏差 > 20% 时自动调整滑点/手续费模型
- Loop 4（钱包淘汰）：评分低于阈值或连续 14 天无活跃交易的钱包自动移出候选池
- Loop 5（参数自优化）：每 7 天根据最新回测结果自动微调评分权重（调整幅度 ≤ 5%）

**Achievable**: 使用定时任务（Cron）和监控脚本实现，调整逻辑使用规则引擎。

**Relevant**: 这是用户明确要求的核心模式，确保系统长期稳定运行。

**Time-bound**: 与 1.3/1.4 并行开发，2 个工作日完成框架，持续运行优化。

**Specific**: 生成阶段1的全部输出物，包括钱包白名单、评分报告、回测结果、配置文件，并完成阶段验收。

**Measurable**:

## 3. 算法/逻辑设计

### 3.1 候选池过滤流水线（Pipeline）

```
原始地址流（GMGN）
    │
    ▼
┌──────────────────┐
│  Step 1: 基础过滤 │  排除 7 天交易 > 500 次（机器人）
│  活跃度过滤       │  过去 30 天交易 < 10 次（不活跃）
└──────────────────┘
    │ 通过率目标：~40%（原始 25,000 → 10,000）
    ▼
┌──────────────────┐
│  Step 2: 财务过滤 │  总利润 < $30K（排除新手/亏损）
│  盈利能力验证     │  单笔投资 < $500 或 > $10K（排除异常规模）
└──────────────────┘
    │ 通过率目标：~50%（10,000 → 5,000）
    ▼
┌──────────────────┐
│  Step 3: 行为过滤 │  持仓周期 < 24h（排除快进快出）
│  交易模式分析     │  胜率 < 60%（排除赌徒）
│                  │  稳定币持仓 < 总资产 10%（排除无风控）
└──────────────────┘
    │ 通过率目标：~100%（精筛，5,000 → 5,000）
    ▼
候选池（Candidate Pool）
```

**关键过滤条件 SQL 伪代码**：

```sql
SELECT wallet_address
FROM wallet_stats_30d
WHERE 
  -- 排除机器人
  tx_count_7d BETWEEN 10 AND 500
  
  -- 活跃度要求
  AND tx_count_30d >= 10
  
  -- 盈利能力
  AND total_profit_usd >= 30000
  AND avg_investment_usd BETWEEN 500 AND 10000
  
  -- 胜率
  AND win_rate >= 0.60
  
  -- 持仓周期（平均持仓时间 > 24h）
  AND avg_holding_hours >= 24
  
  -- 稳定币持仓（至少持有总资产 10% 的稳定币）
  AND stablecoin_ratio >= 0.10
  
  -- 排除 Pump.fun 过度集中（>80% 交易在 Pump.fun）
  AND pump_fun_ratio <= 0.80
  
  -- 排除最近 7 天无交易（可能已弃用）
  AND last_trade_at >= datetime('now', '-7 days')
```

### 3.2 多维度评分算法（Scoring Engine）

#### 3.2.1 评分维度与权重（默认配置，可热调整）

| 维度 | 权重 | 说明 | 计算方式 |
|------|------|------|----------|
| **盈利能力** (Profitability) | 30% | 综合收益率和利润额 | 归一化（对数变换）后百分位排名 |
| **胜率** (Win Rate) | 25% | 盈利交易占比 | 原始胜率 × 交易量调整因子 |
| **风险控制** (Risk Control) | 20% | 最大回撤、止损执行率 | 100 - max_drawdown_pct（归一化） |
| **一致性** (Consistency) | 15% | 收益稳定性（月度胜率） | 月度胜率标准差的倒数 |
| **活跃度** (Activity) | 10% | 交易频率与持续性 | 每周交易次数在 50-100 范围内的得分最高 |

#### 3.2.2 评分公式

```python
def calculate_wallet_score(wallet_stats, weights):
    """
    计算钱包综合评分
    """
    scores = {}
    
    # 1. 盈利能力 (Profitability)
    # 使用对数变换处理极端收益，避免被异常值主导
    log_roi = math.log10(max(1, wallet_stats['total_roi_pct']))
    scores['profitability'] = min(100, log_roi / 3 * 100)  # 1000% ROI = 100分
    
    # 2. 胜率 (Win Rate)
    win_rate = wallet_stats['win_rate']
    tx_count = wallet_stats['total_trades']
    # 交易量调整：至少 50 笔交易才给满分，<20 笔大幅折扣
    volume_factor = min(1.0, tx_count / 50)
    scores['winrate'] = win_rate * 100 * volume_factor
    
    # 3. 风险控制 (Risk Control)
    max_dd = wallet_stats['max_drawdown_pct']
    # 最大回撤越小越好，0 回撤 = 100 分，-80% 回撤 = 0 分
    scores['risk_control'] = max(0, 100 + max_dd * 1.25)  # -80% -> 0, 0% -> 100
    
    # 4. 一致性 (Consistency)
    monthly_returns = wallet_stats['monthly_returns']  # 最近 6 个月
    if len(monthly_returns) >= 3:
        std = statistics.stdev(monthly_returns)
        mean = statistics.mean(monthly_returns)
        # 变异系数越小越好，月均收益 > 0 加分
        cv = std / abs(mean) if mean != 0 else 999
        scores['consistency'] = max(0, min(100, 100 - cv * 30 + (mean > 0) * 20))
    else:
        scores['consistency'] = 50  # 数据不足给中性分
    
    # 5. 活跃度 (Activity)
    weekly_tx = wallet_stats['avg_weekly_trades']
    # 理想区间 50-100，低于 20 或高于 150 扣分
    if 50 <= weekly_tx <= 100:
        scores['activity'] = 100
    elif 20 <= weekly_tx < 50 or 100 < weekly_tx <= 150:
        scores['activity'] = 70
    else:
        scores['activity'] = 30
    
    # 加权求和
    total = sum(scores[k] * weights[k] for k in scores)
    return {
        'total_score': round(total, 2),
        'dimensions': {k: round(v, 2) for k, v in scores.items()},
        'weights': weights
    }
```

#### 3.2.3 权重自优化（Loop 5）

每 7 天运行一次：
1. 取过去 7 天 Top 50 钱包的评分与实际收益（回测模拟跟踪）
2. 计算评分与实际收益的相关性（Pearson r）
3. 如果 r < 0.5，说明评分对收益的预测力不足，触发权重微调
4. 使用网格搜索（步长 5%）在权重空间中寻找最优组合，约束条件：
   - 每个权重在 [0.05, 0.50] 范围内
   - 权重总和 = 1.0
   - 单维度权重变化 ≤ 5%
5. 更新权重配置，记录到 `LoopLog`

```python
def backtest_wallet(wallet_address, strategy, start_date, end_date, initial_capital=10.0):
    """
    对单个钱包执行历史回测
    
    Args:
        wallet_address: 目标钱包地址
        strategy: 策略配置字典
        start_date, end_date: 回测时间区间
        initial_capital: 初始 SOL 资金（默认 10 SOL）
    
    Returns:
        BacktestResult 对象
    """
    # 1. 获取该钱包在区间内的所有买入事件（按时间排序）
    buy_events = fetch_wallet_buys(wallet_address, start_date, end_date)
    
    capital = initial_capital  # 当前可用资金
    positions = {}             # 当前持仓: {token_address: {amount, cost_basis, buy_time}}
    trades_log = []            # 每笔模拟交易的日志
    equity_curve = [(start_date, initial_capital)]  # 权益曲线
    
    # 按时间顺序处理每个买入事件
    for buy_event in buy_events:
        # 确定买入金额
        if strategy['buy_mode'] == 'fixed_buy':
            buy_amount = min(strategy['buy_amount_sol'], capital * 0.1)
        elif strategy['buy_mode'] == 'fixed_ratio':
            buy_amount = capital * strategy['buy_ratio']
        elif strategy['buy_mode'] == 'max_buy':
            buy_amount = buy_event['amount_sol']  # 跟随钱包实际买入量
        
        if buy_amount <= 0 or buy_amount > capital:
            continue  # 资金不足，跳过
        
        # 扣除手续费和滑点后的实际花费
        fee = buy_amount * strategy['fee_pct'] / 100
        slippage = buy_amount * strategy['slippage_pct'] / 100
        actual_cost = buy_amount + fee + slippage
        
        if actual_cost > capital:
            continue
        
        capital -= actual_cost
        
        # 记录持仓
        token = buy_event['token_address']
        token_amount = buy_amount / buy_event['price']
        
        if token in positions:
            # 加仓：更新成本基准
            old = positions[token]
            total_amount = old['amount'] + token_amount
            avg_cost = (old['amount'] * old['cost_basis'] + token_amount * buy_event['price']) / total_amount
            positions[token] = {
                'amount': total_amount,
                'cost_basis': avg_cost,
                'buy_time': old['buy_time']
            }
        else:
            positions[token] = {
                'amount': token_amount,
                'cost_basis': buy_event['price'],
                'buy_time': buy_event['timestamp']
            }
        
        trades_log.append({
            'type': 'buy',
            'time': buy_event['timestamp'],
            'token': token,
            'amount_sol': buy_amount,
            'fee': fee,
            'slippage': slippage,
            'capital_after': capital
        })
        
        # 检查该代币后续的卖出/价格变化，触发止盈止损
        # 获取该代币在买入后的所有价格点
        price_history = get_token_price_history(token, buy_event['timestamp'])
        
        for price_point in price_history:
            current_price = price_point['price_sol']
            pnl_pct = (current_price - positions[token]['cost_basis']) / positions[token]['cost_basis'] * 100
            
            # 检查止损
            if pnl_pct <= strategy['stop_loss_pct']:
                sell_amount = positions[token]['amount']
                gross_value = sell_amount * current_price
                sell_fee = gross_value * strategy['fee_pct'] / 100
                sell_slippage = gross_value * strategy['slippage_pct'] / 100
                net_value = gross_value - sell_fee - sell_slippage
                
                capital += net_value
                
                trades_log.append({
                    'type': 'sell',
                    'time': price_point['timestamp'],
                    'token': token,
                    'reason': 'stop_loss',
                    'sell_price': current_price,
                    'pnl_pct': pnl_pct,
                    'capital_after': capital
                })
                
                del positions[token]
                break
            
            # 检查分批止盈
            for tp in strategy['take_profit']:
                if pnl_pct >= tp['pct'] and positions[token]['amount'] > 0:
                    sell_pct = tp['sell_pct'] / 100
                    sell_amount = positions[token]['amount'] * sell_pct
                    
                    gross_value = sell_amount * current_price
                    sell_fee = gross_value * strategy['fee_pct'] / 100
                    sell_slippage = gross_value * strategy['slippage_pct'] / 100
                    net_value = gross_value - sell_fee - sell_slippage
                    
                    capital += net_value
                    positions[token]['amount'] -= sell_amount
                    
                    trades_log.append({
                        'type': 'sell',
                        'time': price_point['timestamp'],
                        'token': token,
                        'reason': f'take_profit_{tp["pct"]}pct',
                        'sell_price': current_price,
                        'pnl_pct': pnl_pct,
                        'capital_after': capital
                    })
                    
                    if positions[token]['amount'] <= 0:
                        del positions[token]
                        break
    
    # 回测结束：清算剩余持仓（按当前价格或最后已知价格）
    for token, pos in list(positions.items()):
        last_price = get_last_known_price(token, end_date)
        gross_value = pos['amount'] * last_price
        sell_fee = gross_value * strategy['fee_pct'] / 100
        sell_slippage = gross_value * strategy['slippage_pct'] / 100
        capital += gross_value - sell_fee - sell_slippage
    
    # 计算回测指标
    total_return = (capital - initial_capital) / initial_capital * 100
    
    # 从 trades_log 计算最大回撤、夏普等
    # ... (省略详细计算)
    
    return BacktestResult(
        wallet_address=wallet_address,
        strategy_name=strategy['name'],
        total_return_pct=total_return,
        # ... 其他指标
        trades_log=trades_log
    )
```

### 3.4 机器人检测算法（关键过滤）

```python
def detect_bot_wallet(wallet_stats):
    """
    机器人检测评分，0-100，≥70 视为机器人
    """
    score = 0
    
    # 1. 交易频率异常（权重 40%）
    tx_per_hour_7d = wallet_stats['tx_count_7d'] / (7 * 24)
    if tx_per_hour_7d > 3:  # 每小时 > 3 笔
        score += 40
    elif tx_per_hour_7d > 1.5:
        score += 25
    
    # 2. 交易间隔一致性（权重 30%）
    # 人类交易间隔有随机性，机器人间隔非常规律
    intervals = wallet_stats['trade_intervals_seconds']  # 交易间隔列表
    if len(intervals) >= 20:
        cv = statistics.stdev(intervals) / statistics.mean(intervals)
        if cv < 0.2:  # 变异系数 < 20% = 高度规律
            score += 30
        elif cv < 0.5:
            score += 15
    
    # 3. 买入-卖出时间差（权重 20%）
    # 机器人常在极短时间内完成买卖
    avg_hold_time = wallet_stats['avg_holding_minutes']
    if avg_hold_time < 5:  # 平均持仓 < 5 分钟
        score += 20
    elif avg_hold_time < 30:
        score += 10
    
    # 4.  Gas 费用模式（权重 10%）
    # 机器人总是使用固定 Gas
    fee_std = wallet_stats['fee_std_dev']
    if fee_std < 0.001:  # 几乎固定
        score += 10
    
    return score
```

## 4. Loop Engineering 反馈循环（5 个闭环）

> **设计原则**：每个 Loop 包含 **触发器 (Trigger) → 执行器 (Action) → 验证器 (Validator) → 日志 (Log)** 四个环节。

### 4.1 Loop 1：数据质量监控（Data Quality Loop）

```
┌─────────────────────────────────────────────────────┐
│  触发器: 每日定时检查 + 实时异常检测                   │
│  - 连续 5 次请求失败                                   │

├─────────────────────────────────────────────────────┤
│  执行器:                                               │
│  1. 立即暂停该数据源的数据写入（标记 dirty）            │
│  2. 触发重抓机制（指数退避重试，最多 5 次）             │
│  3. 重抓失败则切换备用数据源（gmgn-cli / gmgnapi）      │
│  4. 校验通过后恢复写入，标记 clean                      │
│  5. 超过 30 分钟无法恢复则告警（Feishu/Console）       │
├─────────────────────────────────────────────────────┤
│  验证器: 重抓数据与已存数据 diff，冲突率 < 2% 通过      │
```

```python
# cron: 每 5 分钟运行一次
class DataQualityLoop:
    def check(self):
        issues = []
        
        # 检查 1：请求失败率
        fail_rate = self.get_fail_rate(minutes=10)
        if fail_rate > 0.05:
            issues.append(('high_fail_rate', fail_rate))
        
        # 检查 2：字段缺失率
        missing_rate = self.get_missing_field_rate(hours=1)
        if missing_rate > 0.05:
            issues.append(('missing_fields', missing_rate))
        
        # 检查 3：价格异常
        price_anomalies = self.find_price_anomalies(threshold=10.0)
        if price_anomalies:
            issues.append(('price_anomaly', len(price_anomalies)))
        
        # 检查 4：交易矛盾（同一 tx_hash 不同数据）
        conflicts = self.find_conflicting_trades(hours=1)
        if conflicts:
            issues.append(('conflicting_data', len(conflicts)))
        
        if issues:
            self.trigger(issues)
    
    def trigger(self, issues):
        # 暂停写入
        self.pause_ingestion()
        
        for issue_type, detail in issues:
            # 指数退避重试
            for attempt in range(5):
                wait = 2 ** attempt
                time.sleep(wait)
                
                if self.retry_fetch(issue_type, detail):
                    self.verify_and_resume()
                    break
            else:
                # 5 次都失败，切换备用源
                if self.switch_to_backup():
                    self.verify_and_resume()
                else:
                    self.alert(f"DataQualityLoop failed: {issue_type}")
        
        self.log_loop('data_quality', issues, 'executed' if self.resolved else 'failed')
```

```
┌─────────────────────────────────────────────────────┐
```

```
│     c. 约束：单维度调整幅度 ≤ 5%（避免剧变）             │
│     d. 目标：最大化 r（评分与收益的线性相关）            │
```

```python
class WeightOptimizer:
    def optimize(self, wallets_with_scores_and_returns):
        """
        使用约束网格搜索优化评分权重
        """
        current_weights = self.load_current_weights()
        current_r = self.calculate_correlation(wallets_with_scores_and_returns, current_weights)
        
        if current_r >= 0.5:
            return current_weights, current_r, 'no_change'
        
        # 约束网格搜索
        dimensions = ['profitability', 'winrate', 'risk_control', 'consistency', 'activity']
        best_weights = current_weights
        best_r = current_r
        
        # 每次只调整一个维度，幅度 ±5%
        for dim in dimensions:
            for delta in [-0.05, 0.05]:
                new_weights = current_weights.copy()
                new_weights[dim] += delta
                
                # 归一化到总和为 1
                total = sum(new_weights.values())
                new_weights = {k: v/total for k, v in new_weights.items()}
                
                # 检查约束
                if not all(0.05 <= v <= 0.50 for v in new_weights.values()):
                    continue
                
                r = self.calculate_correlation(wallets_with_scores_and_returns, new_weights)
                if r > best_r:
                    best_r = r
                    best_weights = new_weights
        
        if best_r > current_r + 0.05:
            self.save_weights(best_weights)
            return best_weights, best_r, 'optimized'
        
        return current_weights, current_r, 'no_improvement'
```

## 5. 验收标准（Exit Criteria）

阶段1 的整体验收需满足以下 **全部条件**：

| # | 验收项 | 标准 | 验证方法 |
|---|--------|------|----------|
| 1 | 数据管道稳定性 | 过去 7 天请求成功率 ≥ 95% | 查询 `loop_log` 中 `data_quality` 记录 |
| 2 | 候选池规模 | active 钱包 ≥ 5,000 | `SELECT COUNT(*) FROM wallet WHERE status = 'active'` |
| 3 | 评分引擎就绪 | 支持 5 维度评分，计算延迟 < 50ms/钱包 | 压测脚本：1000 钱包批处理 |
| 4 | 回测覆盖 | Top 100 钱包完成回测 | `SELECT COUNT(DISTINCT wallet_address) FROM backtest_result` |
| 5 | 回测质量 | 回测偏差 < 15%（对比实时跟踪） | Loop 3 日志显示 7 日偏差 ≤ 15% |
| 6 | 白名单输出 | ≥ 50 个评分 ≥ 70 的钱包 | `whitelist.json` 验证 |
| 7 | 机器人过滤 | 白名单中无机器人（bot_score < 70） | 机器人检测算法扫描 |
| 8 | Loop 部署 | 5 个 Loop 全部运行 ≥ 7 天无报错 | 检查 cron 日志和 `loop_log` 表 |
| 9 | 文档完备 | 输出 Markdown 报告 + JSON 白名单 | 文件存在性检查 |
| 10 | 阶段2就绪 | 白名单 JSON 可被阶段2直接读取 | 阶段2 读取测试 |

**阶段1 完成判定**：
- 10 项验收标准中至少 **9 项通过**（允许 1 项非核心项放宽）
- 必须通过的项：1、2、5、6、8
- 可放宽的项：4（如仅回测 80 个钱包但质量达标）、7（如 1-2 个边界钱包可人工审核）

## 6. 失败回退策略（Failure Recovery）

### 6.1 子目标级回退

| 失败场景 | 回退策略 | 触发条件 | 恢复路径 |
|----------|----------|----------|----------|
| GMGN 服务不可用 | 切换到备用数据源（社区 API / 缓存数据） | 连续 30 分钟请求失败率 > 50% | 服务恢复后自动切换回主源 |
| 数据抓取被限流 | 自适应降速 + 指数退避 + 请求队列 | 收到 429 响应 | 降速至 1 次/秒，逐步恢复 |
| 评分算法偏差大 | 回退到简单规则（仅按收益率排序） | Top 20 回测收益 < 0% | 禁用复杂评分，使用基础过滤 |
| 回测数据不足 | 缩短回测周期（90d → 30d）或扩大钱包范围 | 可用历史数据 < 30 天 | 使用更短周期 + 更宽滑点 |
| 机器人检测误杀 | 人工审核队列 + 白名单机制 | 历史优质钱包被标记 excluded | 加入 `verified_humans` 白名单 |
| Loop 5 优化失败 | 锁定权重为默认配置，停止自优化 | 连续 3 周优化后 r < 0.3 | 人工审查权重逻辑 |
| 数据库损坏 | 从每日自动备份恢复 | 数据完整性校验失败 | 恢复最近备份，重抓缺失数据 |

### 6.2 全局回退（阶段1 整体失败）

如果阶段1 无法在预期时间内完成（如 2 周后仍有 >3 项验收标准未通过）：

1. **最小可行产品 (MVP) 路径**：
   - 放弃自动评分和回测，使用简单规则手动筛选 50 个钱包
   - 规则：胜率 > 60%、总利润 > $50K、过去 30 天活跃、非机器人
   - 输出简化版白名单，直接进入阶段2（手动跟单验证）

2. **数据驱动降级**：
   - 如果 GMGN 数据完全不可用，使用公开链上数据（SolanaFM / Helius）
   - 基于 DEX 交易记录手动计算钱包指标

3. **时间盒策略**：
   - 每个子目标设定硬 deadline（如 1.3 评分引擎最多 5 个工作日）
   - 超时则使用当前最佳方案，标记为 `degraded`，继续推进

### 6.3 灾难恢复（Data Recovery）

```yaml
backup_strategy:
  frequency: daily
  retention: 30 days
  targets:
    - SQLite 数据库文件（含 WAL）
    - 原始 GMGN 响应 JSON（按日分区）
    - 配置文件（weights.json, strategies.json）
  storage:
    - 本地: /data/backups/
    - 远程: 百度网盘 / NAS WebDAV（用户已有配置）
  recovery_rpo: 24 hours  # 最多丢失 24 小时数据
  recovery_rto: 2 hours   # 2 小时内恢复服务
```

## 8. 风险与安全

### 8.1 数据安全
- 私钥模板存储在 `~/.config/gmgn/.env`，权限严格设为 `600`
- 阶段1 不涉及真实私钥，仅使用空模板
- 所有敏感配置使用 `pydantic.SecretStr` 防止日志泄露

### 8.2 数据抓取合规
- 严格遵守 2 次/秒限速，避免触发 GMGN 封禁
- 使用动态 User-Agent 和请求头（如需要）
- 优先使用官方/社区工具（gmgn-cli, gmgnapi），避免自行逆向

### 8.3 回测局限性（必须理解）
- 历史数据不代表未来表现
- GMGN 数据可能有延迟，回测假设 "看到即买入" 可能过于乐观
- 滑点模型在极端行情（Meme coin 暴涨暴跌）中可能严重低估
- Pump.fun 代币 98.6% 未毕业归零，回测必须区分毕业/未毕业

### 9.3 数据库初始化脚本（init_db.sql）

```sql
-- 数据库初始化脚本
-- 运行: sqlite3 gmgn.db < init_db.sql

PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;

CREATE TABLE IF NOT EXISTS wallet (
    address TEXT PRIMARY KEY,
    first_seen_at DATETIME NOT NULL DEFAULT (datetime('now')),
    last_active_at DATETIME NOT NULL DEFAULT (datetime('now')),
    status TEXT NOT NULL DEFAULT 'active' CHECK(status IN ('active', 'suspended', 'excluded')),
    exclusion_reason TEXT,
    tags JSON,
    metadata JSON
);

CREATE INDEX IF NOT EXISTS idx_wallet_status ON wallet(status);
CREATE INDEX IF NOT EXISTS idx_wallet_last_active ON wallet(last_active_at);

CREATE TABLE IF NOT EXISTS trade (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    wallet_address TEXT NOT NULL,
    token_address TEXT NOT NULL,
    tx_hash TEXT UNIQUE NOT NULL,
    direction TEXT NOT NULL CHECK(direction IN ('buy', 'sell')),
    amount_sol DECIMAL(18,9) NOT NULL,
    amount_token DECIMAL(36,0) NOT NULL,
    price_sol_per_token DECIMAL(36,18) NOT NULL,
    timestamp DATETIME NOT NULL,
    slippage_pct DECIMAL(5,2),
    fee_sol DECIMAL(18,9) NOT NULL DEFAULT 0,
    is_pump_fun BOOLEAN NOT NULL DEFAULT 0,
    is_graduated BOOLEAN NOT NULL DEFAULT 0,
    raw_data JSON,
    FOREIGN KEY (wallet_address) REFERENCES wallet(address)
);

CREATE INDEX IF NOT EXISTS idx_trade_wallet ON trade(wallet_address);
CREATE INDEX IF NOT EXISTS idx_trade_token ON trade(token_address);
CREATE INDEX IF NOT EXISTS idx_trade_time ON trade(timestamp);
CREATE INDEX IF NOT EXISTS idx_trade_tx ON trade(tx_hash);

CREATE TABLE IF NOT EXISTS token (
    address TEXT PRIMARY KEY,
    symbol TEXT NOT NULL,
    name TEXT,
    created_at DATETIME,
    is_pump_fun BOOLEAN NOT NULL DEFAULT 0,
    graduated_at DATETIME,
    current_price_sol DECIMAL(36,18),
    rugged_at DATETIME,
    metadata JSON
);

CREATE TABLE IF NOT EXISTS wallet_score (
    wallet_address TEXT PRIMARY KEY,
    calculated_at DATETIME NOT NULL,
    total_score DECIMAL(5,2) NOT NULL,
    dimension_scores JSON NOT NULL,
    weights_used JSON NOT NULL,
    rank INTEGER NOT NULL,
    percentile DECIMAL(5,2) NOT NULL,
    FOREIGN KEY (wallet_address) REFERENCES wallet(address)
);

CREATE INDEX IF NOT EXISTS idx_score_rank ON wallet_score(rank);
CREATE INDEX IF NOT EXISTS idx_score_total ON wallet_score(total_score DESC);

CREATE TABLE IF NOT EXISTS backtest_result (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    wallet_address TEXT NOT NULL,
    strategy_name TEXT NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    initial_capital DECIMAL(18,9) NOT NULL,
    final_capital DECIMAL(18,9) NOT NULL,
    total_return_pct DECIMAL(8,2) NOT NULL,
    max_drawdown_pct DECIMAL(8,2) NOT NULL,
    sharpe_ratio DECIMAL(6,3),
    win_rate DECIMAL(5,2) NOT NULL,
    profit_factor DECIMAL(6,3),
    total_trades INTEGER NOT NULL,
    avg_trade_return_pct DECIMAL(8,2),
    params JSON NOT NULL,
    trades_log JSON NOT NULL,
    calculated_at DATETIME NOT NULL,
    FOREIGN KEY (wallet_address) REFERENCES wallet(address)
);

CREATE INDEX IF NOT EXISTS idx_backtest_wallet ON backtest_result(wallet_address);
CREATE INDEX IF NOT EXISTS idx_backtest_strategy ON backtest_result(strategy_name);

CREATE TABLE IF NOT EXISTS loop_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    loop_name TEXT NOT NULL,
    triggered_at DATETIME NOT NULL,
    trigger_reason TEXT NOT NULL,
    action_taken TEXT NOT NULL,
    params_before JSON,
    params_after JSON,
    status TEXT NOT NULL CHECK(status IN ('triggered', 'executed', 'failed')),
    error_message TEXT
);

CREATE INDEX IF NOT EXISTS idx_loop_name ON loop_log(loop_name);
CREATE INDEX IF NOT EXISTS idx_loop_time ON loop_log(triggered_at);

-- 视图：活跃钱包统计
CREATE VIEW IF NOT EXISTS v_active_wallet_stats AS
SELECT 
    w.address,
    w.status,
    COUNT(t.id) as total_trades,
    SUM(CASE WHEN t.direction = 'sell' THEN t.amount_sol ELSE 0 END) as total_sold,
    AVG(t.amount_sol) as avg_trade_size,
    MAX(t.timestamp) as last_trade_time
FROM wallet w
LEFT JOIN trade t ON w.address = t.wallet_address
WHERE w.status = 'active'
GROUP BY w.address;
```
